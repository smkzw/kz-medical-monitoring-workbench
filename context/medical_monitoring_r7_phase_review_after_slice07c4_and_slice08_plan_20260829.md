## 3. 后续顺序

1. **Slice-08：三模式跨 Run 连续性。** 建立已发布运行之间的医学决定版本、风险转移、模式输出和可复用产物 carry-forward；synthetic 全量、日常增量、锁库前修订增量、核查前固定总量四类场景必须闭合。
2. **Slice-09：本地产品韧性。** 项目级备份/恢复/导入导出、迁移/升级/失败回滚、审计链核验、日志轮转、安装/卸载数据处置，以及不依赖真实项目的分级性能与长任务基准。
3. **R7 总体复核。** 仅当 Slice-08/09 均完成，三模式图、失败恢复、备份迁移、审计与容量证据齐全，才能评估 R7 是否完成。
4. **R8 准备门。** R7 接受后另行冻结五项目只读输入、隔离输出、角色覆盖与缺陷判定；不得以本阶段 synthetic 证据直接启动真实项目。

## 4. Slice-08 用户任务

- 日常增量：用户选择本次完整 listing，系统自动推荐同项目上一已发布日常结果；页面优先告诉用户本轮新增、升级、持续和需重新判断的中高风险。
- 锁库前：用户选择 query 后修订批次时，系统区分有证据的 Query 关联变化与一般数据修订，不凭时间先后推断因果；多轮结果仍可回看。
- 核查前：每次运行固定总量与医学决定版本，后续任何数据或规则变化只能创建新运行，旧结果保持原样。
- Patient Journey：风险状态变化和相关事件继续落到同一访视/时间轴；点击变化项可回到本轮与上一轮的来源证据，不用理解内部 run、hash 或 artifact 术语。
