# 医学监查 P10：RUX-03-002 历史增量来源验证

**验证日期：** 2026-07-30  
**工作方式：** 只读检查原始项目文件；未修改来源文件、运行数据库或产品代码，未导入生产，未创建测试项目  
**允许写入：** 仅本报告  
**结论用途：** P10 增量/diff E2E 来源选型，不等同于生产导入或发布放行

## 1. 结论

### 1.1 主结论

1. **最佳历史基线是 2025-04-16 文件。** 它可作为隔离测试环境中的真实早期
   **项目级全量 EDC listing**，与已登记的 2025-06-12 当前快照组成真实时间增量对。
2. 该文件应登记为 **B 级、处理后全量快照**，不能登记成 A 级原始导出：
   - 物理上覆盖与当前快照相同的 53 个核心 EDC sheets，另有 `Code_List`；
   - 没有中心筛选标记，没有人工量表比较 sheet，没有公式、批注、外链、VBA 或 drawing；
   - 但文件名仍带“附量表间评分变化比较”，工作簿由 Apache POI 创建后又由人员重存，
     且本地未找到同日期未经重存的原始导出或压缩包，故无法证明核心 sheets 从导出后
     byte-for-byte 未被人工改动。
3. **2025-03-24、2025-02-24 可作次选基线。** 两者同样保留完整 53-sheet EDC
   主体，schema 是 2025-06-12 schema 的严格子集；但各多一个人工比较 sheet，
   导入前必须由来源分类器明确排除该 sheet。
4. **2024-09-10 至 2025-01-21 的五个文件仅条件可用。** 它们看起来仍是当时的
   项目级全量 listing，而非中心子集；但使用较老的 `GROUPID` 导出结构，缺失后续
   `VISTREP`、`FORMREP`、`VISTOID`、`FORMOID` 等字段，并带人工比较/审核痕迹。
   它们适合验证 schema drift、映射和失败关闭，不宜作为首个 P10 增量主基线。

### 1.2 两个不同的验收结论

| 验收问题 | 结论 |
|---|---|
| 是否有真实早期全项目快照可用于隔离环境的增量/diff E2E？ | **有。首选 2025-04-16。** |
| 是否有可直接作为 A 级来源权威、无需额外 provenance 说明的早期原始导出？ | **没有。** 八个历史文件均存在人工重存或人工比较附件语义。 |

因此，P10 可以用 2025-04-16 完成**产品链路和真实时间差异验证**，但不能据此把
“历史来源权威通过”标为 A 级通过。若发布门强制要求一对 A 级未经人工处理的连续原始
导出，则必须另行取得历史原始导出；本地现有候选不能满足该门。
