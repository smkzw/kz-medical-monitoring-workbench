## 1. 阶段结论

Slice-09A 至 09D 已分别闭合项目级备份恢复、schema 升级回滚、业务审计与日志轮转、性能容量与长任务恢复的 synthetic/offline 证据。当前不能接受 R7 整体完成：R7 实施计划第 9 项“安装、首次启动、升级和卸载数据处置说明”没有独立实现与验收，Slice-03 也明确把正式分发打包留到后续。

Slice-09E 现已按 `ACCEPT_R7_SLICE_09E_LOCAL_DISTRIBUTION_SYNTHETIC_OFFLINE` 完成窄范围验收。该验收补齐了本地管理入口、首次检查、升级准备和卸载数据处置的合成离线事实，但明确不等于真实安装包、真实运行就绪或无需命令行的桌面应用。R7 是否可以用“synthetic/offline 工程基线完成”收口，必须由本次阶段独立复核决定，不能把 09E 的窄接受直接外推为 R7 全量接受。

## 3. Slice-09E 用户价值

- 用户只需使用一个中文入口完成启动、停止、状态检查和打开工作台，不必手工管理 8911/5174、数据库或终端命令。
- 首次启动先检查本机运行条件和配置，缺项用中文说明并停止，不创建半初始化项目。
- 升级前自动调用 09A/09B 已接受的备份与兼容性检查；失败保持原版本和原数据可用。
- 卸载默认只移除应用，不删除项目数据、备份或导出；数据清除必须是独立、显式、可预览的操作。
- 所有说明使用医学工作台用户语言，不显示内部表名、hash、端口、进程或开发日志。

## 4. 09E 最小边界

09E 仅新增医学监查专属的本地分发/运维入口、离线结构验证、中文说明和证据清单。复用现有后端、前端、09A 备份、09B 迁移、09C 核验能力；不复制这些实现，不修改 `deploy/medical_writing_local`，不引入新依赖。

本切不做 Windows 分发、签名安装器、自动更新、移动端适配、安全设计/测试、真实项目/模型/浏览器运行，也不宣称已形成可对外发布的安装包。

## 6. 09E 完成后的阶段复核问题

### 已闭合的工程基线

- 十项计划均已有对应代码、合同、测试或可追溯的受限验收记录。
- 三模式运行、跨 Run 决定连续性、真实进度、后台恢复、harness adapter、备份迁移、审计日志、容量恢复和本地分发处置已形成同一 R7/R1 内核上的 synthetic/offline 闭包。
- Patient Journey 保持唯一横向访视轴，项目/中心具备同源受试者流向看板；前端桌面边界以 1920×1080 至 4K 为正式视觉范围。
- 内置 harness 的默认 MTPLX medium 与显式 DeepSeek V4 Flash max 均有 synthetic 能力接入证据；模型选择未写死在业务对象。

### 不得被阶段结论掩盖的未验证项

1. **真实本地应用形态未验证。** 当前 `deploy/medical_monitoring_local` 是源码与管理壳层；没有安装器、完整运行依赖、start scripts 或真实一键桌面启动证据。
2. **“本地通知”证据不完整。** 进度页有 `aria-live` 与状态播报，用户可离页并回来查看；但全局通知中心仍显示“通知中心尚未开放”，未见独立的离页完成/失败通知验收。
3. **真实备份、迁移、回滚和卸载处置未验证。** 09A–09E 只接受 synthetic/offline；System Design 15.4 的“真实验证”必须在 R8 受控真实来源矩阵完成，不能在 R7 结论中声称已经完成。
4. **医学正确性与跨项目泛化未验证。** 五个真实项目、异构 listing、不同药物/疾病和医学风险结论均未运行；必须由 R8 source-admission 与反过拟合合同约束。
5. **产品容量/SLO 未形成。** 09D 只接受记录工作站、冻结 corpus 和 source-copy 的观测，不是产品支持范围。

### 待独立复核的建议结论

建议只在以下窄口径下接受 R7：`ACCEPT_R7_SYNTHETIC_OFFLINE_ENGINEERING_BASELINE`。它表示 R7 的工程结构和合成离线恢复闭包具备进入 R8 的条件，不表示真实本地应用、真实医学质量、生产、监管或商业化完成。

若独立复核认为“本地通知”或“一键本地应用”必须在 R7 内形成真实用户级证据，则不得接受 R7；应增加最后一个有界修复纵切，而不是把缺口静默转交 R8。

## 7. 独立复核后的最终阶段决定

同 session 独立复核逐条对账 R7 十项要求后选择路径 A。Codex 接受：

`ACCEPT_R7_SYNTHETIC_OFFLINE_ENGINEERING_BASELINE`

该状态只表示 R7 工程结构、合成离线三模式闭包、恢复/审计/备份迁移/容量观察及中文管理壳层达到进入 R8-0 合同冻结的条件。它不表示真实本地应用、离页通知中心、真实项目或模型医学质量、真实安装/迁移、生产、监管或商业化完成。

R8-0 必须先冻结并独立接受以下门禁，全部通过前不得读取五个真实项目：

1. source-admission：只读来源清单、逐文件哈希、项目隔离输出与最小披露；
2. anti-overfit：禁止把项目、药物、疾病、评分、风险、列名或表格布局硬编码进通用内核；
3. harness responsibility：listing、药物和疾病语义由独立 harness/LLM 按通用 schema 提取，Codex 只核查身份、覆盖、来源锚点和失败语义；
4. real-app readiness：真实 start-script/依赖/一键入口和无需手工端口管理的可观察证据；
5. local notification：至少提供离页完成/失败信号，或由用户明确接受继续仅使用页面内状态；
6. System Design §15.4：真实来源上的备份、迁移、回滚、卸载处置和浏览器 E2E 验证合同。
