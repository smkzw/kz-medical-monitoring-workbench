# 医学监查字段映射科学性放行矩阵

日期：2026-07-30  
状态：新版字段映射合同的 P0 验收合同；未通过前不得 assemble、confirm 或 activate。

## 1. 放行原则

字段覆盖完整、任务全部 completed、JSON 合同有效均不等于医学语义可采用。每个项目必须
同时通过：

1. 结构完整性：当前冻结批次每个 schema 字段恰好有一个当前候选。
2. 来源一致性：项目、批次版本、来源条目/内容哈希、字段画像和 prompt 合同一致。
3. 医学对象正确：候选识别的是“什么对象、什么事件、什么时间、什么值”，而非仅按 sheet
   缩写猜测。
4. 能力诚实：listing 无法证明的含义必须形成明确能力缺口，不得推定“未发生”或“已完整
   识别”。
5. 跨项目泛化：规则来自证据不变量，不能绑定某个项目字段名、表名或固定剂量。

## 3. 药物对象与动作族

候选必须先识别药物对象，再识别动作。允许的对象至少区分：

- 试验药物；
- 安慰剂或阳性对照；
- 方案规定的非试验用背景治疗；
- 普通非试验用合并用药（CM）；
- 救援治疗；
- 禁止/限制用药线索；
- 对象身份未确认。

试验药物动作必须保持独立：

- administration；
- dose adjustment；
- interruption；
- restart；
- discontinuation；
- dispense；
- return；
- compliance。

域名为 `EX`、字段含 dose/date/time、数值与方案剂量相同，均不能单独证明对象是试验药。
背景治疗不可并入 IP；CM 始终只指非试验用药。缺少药物身份或动作证据时，保留来源原值和
locator，候选降为中性 treatment event，并给出具体待核对证据。

## 4. 数值、日期、量表与编码

- 计划剂量、处方剂量、实际剂量、发放量、回收量、取用量及重复/派生字段不得合并。
- 部分日期必须保留原文、精度、可确定范围和解析状态；不得静默补齐未知年月日。
- 量表总分需结合表单名称、条目字段、取值和标签识别；算术一致只支持“来源总分可核对”，
  未绑定正式版本、条目、条件分支和缺失规则时不得声称工作台已复算。
- MedDRA、药品词典及其他标准编码必须有编码体系、版本、代码/术语关系和来源血缘；
  缺一项时只展示来源 code/term，并限制标准编码能力。

## 5. 能力缺口

下列情况必须明确显示“不支持该批次确定性判断”，而非生成阴性结论：

- 无独立字段族重建 dose adjustment、暂停、恢复、永久停药或其他 IP 变更；
- 无公式/版本复算量表；
- 无编码体系和版本确认标准化编码；
- 无完整日期支持精确时窗；
- 无计划与实际值区分支持依从性或偏差判断；
- 无足够来源关系支持 AE/MH 漏报或跨表因果结论。

## 6. LOOP 验收

1. 新 prompt 合同离线测试通过后，启动产品独立 AI；旧合同自动 stale，禁止迁移旧候选。
2. 先审 MG-K10 已知阻断字段块，全部符合本矩阵后再审该项目完整候选。
3. 再审 RUX 的 IP/CM/编码/量表高风险块和 MY009 的重复字段/来源等级边界。
4. 对失败块修 prompt 或确定性质量门，重新创建新合同；不得直接修运行库候选 JSON。
5. 三项目全量通过后才允许 assemble。组装层再验证跨 chunk 角色一致性、血缘和能力清单。
6. 医学经理确认后激活 mapping；激活只代表该批次映射可用，不代表所有受限能力可用。
