# 医学监查项目/中心受试者流向看板需求补充

日期：2026-08-28  
状态：用户新增需求，后续产品视觉阶段的约束来源

## 1. 目的与适用页面

项目级、中心级默认页均应提供“受试者阶段流向”看板，帮助医学监察员在一屏内回答：

- 受试者当前处于哪个研究阶段；
- 各阶段有多少人、从哪里流入、向哪里流出；
- 筛选失败、未治疗、停药、退出研究等关键分流发生在哪里；
- 哪些分流同时伴随中高风险，点击后可落到受试者与原始依据。

用户上传截图仅作为横向桑基图/河流图的信息结构参考，不作为产品文案、配色或数据定义的
权威来源。界面使用中文原生表达，不照搬截图中的英文标签。

## 2. 数据与语义合同

- 阶段和转移必须来自当前项目的研究方案、实际数据结构及本次运行截止点，不写死固定项目
  阶段，也不为缺失数据伪造状态。
- 典型主链可包括“已签署知情同意 → 筛选 → 入组/随机 → 治疗 → 随访/研究结束”，并按
  数据展开“筛选失败、已入组未治疗、治疗中、永久停药、仍在研究、完成研究、退出研究、
  失访”等分支；不适用、无法判断和数据未提供必须明确区分。
- 每条流向的数量必须可由受试者级状态记录重建；节点数、连线数、下方表格和筛选后的风险
  数量使用同一数据截止点、项目/中心范围与运行版本。
- 同一受试者在同一阶段不得被重复计数；阶段跨越、回退、更正和数据冲突需有确定性归属规则
  与可追溯说明。
- 风险等级不替代研究状态。中高风险以独立标记叠加到节点、连线或受试者明细，不把流向颜色
  直接解释为医学风险。

## 3. 页面与交互

- 默认宽屏应完整展示从左到右的主阶段流向，不要求用户先横向滚动才能理解全局；窄屏降级时
  可使用受控横向滚动或分段浏览，但保持阶段顺序。
- 节点和连线标注中文阶段名称与人数；颜色克制、对比清晰，并以文字、形状或线型补足信息，
  不只依赖颜色。
- 点击节点或连线后，下方表格立即过滤到对应受试者；再次点击或“清除筛选”恢复全量。
- 项目级页面支持按中心过滤和比较；中心级页面默认只显示该中心的真实流向。
- 点击受试者可跳转到同一项目、运行、截止点下的受试者医学旅程，并保留返回时的中心、阶段、
  风险等级和表格筛选上下文。
- 图上优先提示中高风险人数及相较上次运行的新增/升级/持续变化；低风险以聚合方式呈现，避免
  抢占注意力。

## 4. 下方明细表

表格至少包含：受试者、中心、当前阶段、上一阶段、状态变化日期/依据日期、关键分流原因、
中高风险摘要、相较前次运行的变化、数据完整性提示。列名使用医学监察员熟悉的中文，不暴露
内部节点名、模型/provider、哈希、日志、状态码或“正式事实/候选信号/只读”等研发术语。

节点、连线和表格的数量必须双向对账；任何不一致均视为阻断性展示缺陷。分母、截止点、数据
覆盖和无法判断原因应可展开查看，而不是用黑箱综合评分代替。

## 5. 后续验收

- 本补充不改变当前 R7 Slice-04 的持久化运行进度范围；流向看板进入后续产品 UI 纵切。
- 浏览器验收改用 ego(lite)，不再用 Playwright。
- 视觉验收不仅检查能显示和能点击，还要检查阶段顺序、数据对账、医学语义、风险重点、中文
  易读性、宽屏完整性和视觉一致性。
- 到该视觉阶段时，再按当时最新受控路由组织用户指定的视觉角色测试；Codex 复核实际页面与
  数据，不以模型自述作为接受证据。
