# P7 确定性 EDC 元数据映射合同

## 问题

真实 MY009 字段映射中，DD 域纯技术字段分片两次被独立 AI 输出为非 `source_metadata`，触发既有确定性约束：

- `DD.__FORMOID`
- `DD.DOMAIN`

同类 `__*OID`、repeat key、`DOMAIN`、`STUDYID` 等 EDC/数据集技术字段的角色由字段身份即可确定，不需要 AI 推断。继续把它们交给 AI 会浪费调用并使整批映射被模型表述波动阻塞。

## 目标

在字段映射工作流中，对可证明的技术元数据字段生成确定性 `source_metadata` 映射；AI 仅处理仍需医学/数据语义判断的字段。确定性结果必须与 AI 候选进入同一可审计草稿、保留来源字段和生成规则，不得静默伪装为 AI 结论。

## 边界

- 仅可基于封闭白名单/命名规则识别明确技术字段；不把临床业务字段误降级为元数据。
- `DOMAIN`、`STUDYID`、受试者/中心/访视标识等即使可确定为来源采集或元数据，也不得改变其临床关联用途；推荐角色与 metadata kind 必须清晰。
- 对混合分片，只预填确定字段，AI 输出必须精确覆盖剩余字段；最终候选集合仍覆盖原分片全部字段且不重复。
- 确定性映射必须有稳定 provenance、版本和测试；不得直接手工改数据库。
- 不修改医学写作、共享 AI 配置、前端或真实运行库。

## 允许写入

- `services/api/app/monitoring_ai_service.py`
- 必要时新增一个医学监查专用 deterministic mapping 模块
- `tests/test_monitoring_ai_service.py`
- 必要的目标 API 测试

## 成功标准

1. 纯技术字段分片不调用 AI 即可完成一个结构合法、可采用的候选。
2. 混合分片只让 AI 判断非确定字段，并与确定字段无重复合并。
3. AI 若回传确定字段或遗漏非确定字段，仍关闭失败。
4. 现有普通字段、代码/术语/版本和派生字段验证不回退。
5. 目标及相邻测试通过。
