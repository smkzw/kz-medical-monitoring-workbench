# P8-B 风险 Checklist 前端整合合同

## 目标

在 P8-A 后端权威分类与服务端查询合同完成后，把医学风险 Checklist 切换为后端分类、
服务端筛选/排序和稳定分页；同时降低筛选区视觉负担。仅影响医学监查前端，不改医学写作
流程或共享独立 AI 配置。

## 必须保持

- 七列固定为：受试者编号、中心编号、风险级别、风险类别、具体风险项、当前处置、更新时间。
- 每列均可排序或筛选，但不常驻展示七个大输入框。
- 风险详情继续使用同页叠加工作区；不为 Timeline、Patient Profile、AE/MH 联查反复新开页面。
- 原始事实优先于 locator；定位和来源哈希是次级溯源信息。
- Safety/PV 只作附加标记，风险主分类仍来自同一风险台账。
- 用户医学确认与 Query 内部审批是两条独立状态轴；用户确认后不得继续显示“待医学批准”。
- 桌面端优先；不为移动端删减功能。

## 接口与状态

- 风险类别直接使用后端 `risk_category_code`、`risk_category_label`、
  `safety_pv_flag`、`taxonomy_version`。
- 删除标题、理由、标签或自由文本正则推断医学类别的生产路径。
- 排序和筛选传递到服务端封闭参数；浏览器不再先拉取全量快照后自行分类。
- URL/返回状态至少保留：
  - trial/site/subject scope；
  - site_id / subject_id；
  - 当前风险实例；
  - 当前证据页签；
  - Checklist 排序与筛选。
- 快照身份变化、分页不完整或非法查询必须明确失败，不拼接不同快照。

## 交互

- 列头是主要入口：点击列名切换排序；过滤图标打开该列的小型筛选浮层。
- 浮层只显示与该列匹配的控件；应用后以简短条件标签显示在表格上方，可单项清除或全部重置。
- 具体风险项使用关键词查询；更新时间使用明确日期/范围，不使用自由格式隐式解析。
- 风险类别候选来自后端 taxonomy；未知兼容类别显示“其他医学复核”，不在前端猜测细分类。
- 加载时保留表头和稳定尺寸；不显示内部 job、hash、模型日志或长篇警告。

## 验收

- 修改风险标题或理由不改变风险类别。
- 七列排序/筛选均真实触发服务端查询且返回稳定顺序。
- trial/site/subject 范围与筛选可组合，完整 Timeline/Profile 返回后状态不丢失。
- 1440×900、1728×1000 最大化桌面检查无横向页面溢出、无列错位、无文字越界。
- 使用 RUX、MG-K10、MY009 三个真实项目风险验证至少：
  - AE 漏报、MH 漏报；
  - CS/NCS；
  - 禁限用药；
  - 试验药物变更/依从；
  - 访视窗口；
  - 实验室/CTCAE；
  - Safety/PV 附加标记。
