# P7C Gold Case 与影子运行盘点合同

## 目标

基于当前医学监查代码、运行数据库和真实项目来源记录，盘点 P7C 进入影子运行前的 gold case 覆盖、来源绑定、规则类别、跨项目泛化和科学性缺口。只形成可执行差距报告，不修改产品代码和真实运行数据。

## 范围

- 项目：RUX-03-002、MG-K10、MY009；必要时仅以去标识的项目/中心/受试者编号报告。
- 风险类别至少区分：AE 漏报、MH 漏报、CS/NCS 判定不合理、禁用/限制用药 PD、试验药物给药/剂量调整/停药/重启/依从性、访视窗口/方案执行 PD、实验室异常及 CTCAE 趋势、疗效/安全性时间序列。
- CM 仅表示非试验用合并用药或治疗；试验药物变化必须使用 EX/EC/DA/IP 等独立域，不得混淆。
- gold case 必须绑定原始 listing 行、方案条款可读正文与定位、字段映射修订、规则修订和批次；缺任一关键来源不得视为上线 gold。
- 正例、负例、边界例、缺失/不可判定例均需覆盖；“未发现风险”不能替代阴性 gold。
- 不创造医学结论，不修改真实项目数据库，不复用 skill 已解构的后半段产物作为从零测试证据。

## 输出

仅写：
`reviews/monitoring_gold_shadow_p7c_inventory.md`

报告需包含：

1. 阅读的真实来源与代码/数据库表；
2. 现有 gold case 数量和按项目、规则类别、标签的矩阵；
3. 来源链完整性和不可用原因；
4. 影子运行前必须补齐的最小集合；
5. 可自动验证与必须医学经理确认的边界；
6. 跨项目过拟合风险与建议的泛化测试；
7. 下一步可直接执行的任务清单。
