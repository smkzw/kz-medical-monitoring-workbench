# 医学监查 P9 总系统接入主会场验收

日期：2026-07-30

## 结论

P9 通过。医学监查是风险、证据、处置和未读状态的唯一业务写入者；总看板、统一收件箱、
Safety/PV 和旧兼容读取接口均消费持久化快照，不在读取链路重新评估或复制风险。

## 主会场重点审阅

1. 强制项目适配器的风险评估函数抛错后，总看板、收件箱和兼容 GET 仍可读取。
2. 读取 dashboard、旧 GET、收件箱和 current snapshot 前后，风险 SQLite 的 SHA-256、
   大小和 mtime 不变。
3. 共享来源内容投影不暴露本地路径、存储键、内容哈希或全文；共享方案事实只投影已确认、
   有来源修订和 locator 的事实。
4. 前端项目切换会清除旧项目全部医学监查状态；抽屉关闭重新规范化路由，不留下无风险焦点
   的 evidence 视图。
5. Safety/PV 只读投影与医学监查使用同一风险身份、快照、状态与审计，不能执行风险处置。

## 真实运行态观察

- MY009 和 RUX Checklist、风险证据、未读写回、Timeline、Patient Profile 与 Safety/PV
  均完成真实页面点击验收。
- Timeline 以访视为轴，试验药物与非试验用合并用药保持独立泳道。
- 核心证据首先展示原始数据、方案原文和规则判定；locator 为次级信息。
- 当前运行态产品独立 AI 已配置；V10 字段映射仍在后台运行，未自动确认或激活。

## 剩余风险

- Patient Profile 在真实来源存在同日同值多行时会如实显示重复趋势点；P10 需判断是有业务
  含义的重复记录还是应通过稳定来源身份合并的重复展示。
- 当前主会场浏览器视口为 1280x720；独立前端验收已覆盖 1440x900。P10 仍需在更宽桌面
  视口复核信息密度和抽屉遮挡。
- FastAPI `on_event` 弃用和 Vite 大 chunk 为工程维护债，不影响本阶段业务正确性。

override、diff、结构漂移、规则/独立 AI、风险复核、处置、确认、重启恢复和事实视图往返。
