## 3. 已观察到的高优先级问题

### 3.1 RUX：试验药物剂量变更边界

`DAB.DABWDOSE` 当前被候选分类为 `deterministic_derived`，但公式仅为“待用户确认”，不存在可复算、可审计的确定性推导链。

预期处理：

- 在原始 listing 已直接采集该值的前提下，改为 `source_collected`。
- 不得把剂量调整、停药、减量、重启等试验药物变更并入 CM。
- CM 仅代表非试验用药；EX/EC/DA/IP 等试验药物给药或调整域必须独立保留。

### 3.2 RUX：WHODrug/ATC 编码血缘证据不足

以下候选存在“字段看似编码结果，但编码系统或版本证据不足”的问题：

- `CM.ATC1CODE`
- `CM.ATC2CODE`
- `CM.DRUGCODE`
- `CM.DRUGPTCD`

当前部分候选把术语字段当作 `dictionary_version_field`，不符合编码血缘定义。术语、编码值、编码系统、字典版本和语言必须分别表达。

预期处理：

- 未找到明确 coding system/version 证据时，保持或改为 `source_collected`。
- 只有在原始数据、数据字典或明确版本元数据可以证明时，才标记为 `standardized_coded`。
- 不得仅凭字段名或值的数字形态猜测 WHODrug、ATC 或其他字典。

### 3.3 RUX：MedDRA 术语字段来源链错误

AE/MH 中存在真实 `MDRAVER=28.0`、`MDRALANG=cn` 证据，但若干候选的 `source_fields` 指向错误：

- `AE.PTTERM`：不应把自身作为主要来源，应关联 `PTCODE` 及 MedDRA 版本/语言字段。
- `AE.SOCTERM`：不应把自身作为主要来源，应关联 `SOCCODE` 及 MedDRA 版本/语言字段。
- `MH.PTTERM`：当前来源指向 `MHTERM`，需改为 `PTCODE` 及 MedDRA 版本/语言字段。
- `MH.SOCTERM`：当前来源指向 `PTTERM`，需改为 `SOCCODE` 及 MedDRA 版本/语言字段。

预期处理：

- 对 AE、MH 以及可能使用 MedDRA 的 PR 域执行整域血缘复核。
- 术语层级（LLT/PT/HLT/HLGT/SOC）、代码、版本和语言必须相互匹配。
- PR 域若没有足够证据证明使用 MedDRA，不得因存在全局版本字段就自动升级。

### 3.4 MY009：项目内部代码不等于标准编码

`LB9.LBTESTCD` 当前被候选分类为 `standardized_coded`，但已观察值 `HBV_DNA` 只能证明存在项目字段代码，不能证明其来自外部标准字典。

预期处理：

- 在缺少标准字典与版本证据时改为 `source_collected`。
- 项目内部代码、EDC 选项代码和标准医学编码必须分开。

### 3.5 MY009：重复表头后的编码关系缺失

MY009 存在大量 Excel 重复表头，经导入后形成：

- `AETERM__2`、`AETERM__3` 等；
- `MH1TERM__2`、`MH1TERM__3` 等；
- `CM1TRT__2`、`CM1TRT__3` 等。

现有字段剖析器能够统计普通 `TERM/CODE` 同行关系，但规范化时没有保留重复列组的对应关系，导致大量可能的 MedDRA/WHODrug/ATC 术语和代码列被保守判为 `unmapped`。

当前结论：

- 保持 `unmapped` 比错误自动编码更安全。
- 应在字段剖析层补充“相同重复后缀组内的同行共现统计”。
- 该统计只能作为 AI 判断证据，不得自动认定字典、版本、语义或确认映射。
- 后缀不一致的字段不得跨组配对。

### 3.6 MY009：字典版本元数据

`CM1TRT__2` 的 35 个非空值均为 `WHODrug GLOBAL (B3) C [V2025SEP]`，将其识别为字典版本/描述元数据具有数据证据，目前未观察到需修改之处。

该事实不能反向证明其他 `CM1TRT__*` 字段均为同一编码层级，仍需逐列核对。

### 3.7 非编码字段也需要同行关系证据

当前独立 AI 在多个域中正确提出了以下需要同行证据才能确认的关系：

- `SITEID` 与 `SITENM/SITE`；
- `VISIT` 与 `VISTOID/StudyEventOID/VISITNUM`；
- 检查值与单位（如 `PRAG` 与 `PRAG_UNIT`）；
- 是否执行标志与未执行原因；
- 数值剂量与剂量单位；
- “其他”选项标志与自由文本说明。

字段剖析器目前只显式提供 `term_code_pair`。这不会使上述字段映射必然错误，但会迫使 AI 重复要求人工确认本可由数据直接证明的同行共现、一对多或缺失模式。

后续改进边界：

- 增加明确命名的非医学语义关系画像，例如标识-名称、访视 OID-显示名、数值-单位、标志-原因。
- 关系画像只报告共现、单侧缺失、唯一配对和一对多计数，不泄露受试者行值。
- 关系画像不得替代项目主数据、CRF 或医学确认，也不得直接触发正式字段映射。
- 访视、站点和单位关系须按域及真实同一行统计，不能仅因全项目唯一值数量相同就推断一一对应。

## 4. 合理保持未映射的字段

以下字段暂时保持 `unmapped` 是符合边界的：

- RUX `BSARESS`、`BSARESS_UNIT`：取值形态提示可能为 BSA 结果及百分比单位，但仍需 CRF、字段标签或项目数据字典确认。
- MY009 `LBSTRESN`：当前值均为 `"."`，需先确认占位符/缺失值语义。
- MY009 `QTCF`：无法从 listing 单独判断是源采集值还是派生值，需 CRF、数据库设计或推导规范证据。
- 各项目全空字段：不能基于字段名生成确定性医学映射。

## 5. 版本处置决定

V7 候选生成时尚未具备以下当前门禁：

- 严格的编码术语-代码同行关系与独立字典版本字段校验；
- 确定性技术元数据与独立 AI 语义字段的来源分离；
- 重复表头 `__数字` 组内关系画像；
- 站点、访视、数值-单位、执行标志-原因等非编码同行关系画像；
- 非确定公式不得标记为 `deterministic_derived` 的完整限制。

因此：

- V7 完成结果只作为比较基线和独立 AI 行为审计，不直接激活为正式字段映射。
- 两项 V7 技术元数据失败不再是正式映射的阻断项；保留原失败证据即可。只有需要验证受控修复
  机制本身时才调用修复入口，不以修复后的 V7 替代当前版本。
- 旧队列排空后，先备份数据库，再重启 API 加载当前代码，重新生成完整字段画像并提交 V10
  全批次映射。
- V10 候选仍需逐字段医学 QC、显式接受/医学编辑、组装和确认；版本升级不等于自动可信。

## 6. 队列排空后的强制执行顺序

1. 再次导出两项目全部候选、失败项、输入快照和字段关系证据。
2. 对 V7 候选执行全量问题归类，作为 V10 比较基线，重点覆盖：
   - source / derived / coded / metadata / unmapped 边界；
   - AE/MH、CM、试验药物给药与剂量调整边界；
   - MedDRA、WHODrug、ATC 的术语层级、代码、版本、语言和来源字段；
   - 重复表头列组是否被正确配对；
   - 空值、占位符、项目内部代码和真正标准编码的区别。
3. 备份数据库并记录 SHA-256。
4. 重启 API 加载当前代码，重新生成字段画像并提交 V10 全量字段映射。
5. 逐分片比较 V7 与 V10，确认改变来自门禁/证据改进而非随机漂移。
6. 显式接受 V10 合格候选，拒绝或医学编辑不合格候选。
7. 组装草案后再次对完整映射做跨字段、跨域一致性检查。
8. 只有完成项目级医学确认后才可激活映射；不得用测试结果替代正式确认。

## 7. 验收标准

- 每个确认字段均可回答：值从哪里来、是否直接采集、是否推导、是否编码、使用什么系统/版本、依赖哪些源字段。
- CM 与试验药物给药/剂量调整的边界无混淆。
- 不因字段名、模型置信度或跨项目经验直接升级为标准编码。
- 同一编码层级在一个项目内的来源链一致，跨项目允许不同但必须各自有证据。
- 未知项明确保持 `unmapped` 或进入医学编辑，不生成伪确定性结论。

## 8. V10 真实探针发现的字段类型边界

首次 V10 RUX CM 真实分片探针发现，ATC 一级编码集合中的 `N` 被旧字段画像按单值
布尔词识别，从而使 `ATC1CODE` 出现伪 mixed 异常。这属于画像层错误，不属于独立 AI
医学判断错误。

已采用以下通用修正，禁止项目特异硬编码：

- 文本 `Y/N/Yes/No/True/False` 只有在整列全部非空值均为布尔样式时才解释为
  boolean；
- `A/B/C/N` 等单字母编码集合保持 string；
- 布尔样式文本与普通临床文字并存时统一按 string，不把其中的 `N` 单独标异常；
- 原生布尔值及原生布尔值与规范布尔文本的组合仍识别为 boolean。

该修正已通过定向自动回归，正在使用同一原始 listing 和同一 V10 分片重新调用独立 AI
验证。只有真实重跑不再出现该伪异常后，才可认为闭环。
