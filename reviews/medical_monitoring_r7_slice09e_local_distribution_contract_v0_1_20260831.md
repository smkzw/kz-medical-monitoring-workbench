# R7 Slice-09E 本地分发与数据处置合同 v0.1

日期：2026-08-31  
状态：`DRAFT_FOR_INDEPENDENT_REVIEW`

## 1. 目标

在不改动医学写作子系统、不启动真实服务、不读取真实项目的前提下，为医学监查子系统建立可验证的本地应用交付边界：中文的一键启停/状态入口、首次启动检查、升级前保护、失败回滚说明和卸载数据处置。

## 2. 允许路径

- `deploy/medical_monitoring_local/**`
- `tests/test_medical_monitoring_local_distribution.py`
- 与本合同、执行和接受直接相关的 `context/**`、`reviews/**`、`artifacts/**`、`runs/**`
- 只有在无法复用 09A/09B/09C 公共接口时，才可对医学监查 R7 专属模块作最小接线；不得改动医学写作模块或其分发目录。

## 3. 必须实现

### 3.1 中文入口

单一管理脚本提供 `start / stop / status / preflight / prepare-upgrade / uninstall-plan`。用户可见输出只使用“医学监查工作台、启动、停止、运行状态、升级准备、保留项目数据、清除项目数据”等中文表达。内部端口、数据库、进程、表名和路径只进入机器证据，不进入普通成功文案。

### 3.2 首次启动

`preflight` 只检查既有 Python/Node、前端依赖、运行配置、可写数据目录和端口占用；任一缺失均失败关闭并给出一条可执行的中文修复提示。检查不得调用模型、创建真实项目或启动服务。

### 3.3 升级准备

`prepare-upgrade` 必须先使用 09A 的项目备份/清单语义生成临时升级保护证据，再调用 09B 兼容性预检；任一步失败都不得推进版本标记或改写原数据。演练只使用 synthetic 临时工作区。

### 3.4 卸载数据处置

`uninstall-plan` 默认结果必须是“移除应用、保留项目数据与备份”。只有显式 `--include-project-data` 才能生成“同时清除项目数据”的计划；该命令只输出清单和风险提示，不直接删除。真正清理不属于本切，也不得由卸载入口隐式触发。

### 3.5 发布清单

构建器只生成源文件清单、字节数、SHA-256、运行前置条件和范围声明。它不得把凭据、真实项目数据、缓存、日志、数据库、历史测试输出或 `deploy/medical_writing_local` 收入医学监查分发清单。

## 4. 不变量

- 默认数据处置永远保留项目数据、备份和导出。
- 未通过首次启动检查不得产生“已安装/已就绪”状态。
- 升级准备失败不改变原数据、schema 版本或当前可运行版本。
- 09A/09B/09C 是唯一备份、迁移、审计语义来源；09E 不复制第二套机制。
- 任何路径与项目身份必须来自配置/manifest，不硬编码真实研究、药物、疾病、评分或 listing 格式。
- 医学写作文件聚合身份在运行前后不变；8911/5174/8984 全程无监听。

## 5. 验证矩阵

| 场景 | 预期 |
|---|---|
| 完整依赖与配置 | preflight 返回可启动，不启动服务 |
| Python/Node/配置/目录任一缺失 | 中文失败关闭，无副作用 |
| 端口被非本应用占用 | 拒绝启动，不终止外部进程 |
| synthetic 升级准备成功 | 备份与兼容性证据齐全，原工作区不变 |
| 备份或兼容性预检失败 | 不推进版本，不改原数据 |
| 默认卸载计划 | 保留项目数据、备份、导出 |
| 显式数据清除计划 | 仅列出将清除对象，仍不删除 |
| 发布清单 | 无凭据、真实项目、缓存、日志、数据库、医学写作分发文件 |
| 重复执行 | 输出稳定、无额外副作用 |

至少在 `normal/-O/-OO` 与三个 `PYTHONHASHSEED` 下验证清单和处置计划确定性；聚焦测试与 R7 相邻回归必须通过。
