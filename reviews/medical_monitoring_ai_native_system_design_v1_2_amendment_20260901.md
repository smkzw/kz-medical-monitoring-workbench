## 修订 1：§15.1 产品形态（替换）

- 整个医学经理工作台是本地单用户应用；医学监查是其中一个子系统，共享工作台的应用壳、启动方式和本地数据域。**不再单独构建 MedicalMonitoring.app 产品壳。**
- 医学监查后端代码必须收敛为单一 Python package（`packages/medical_monitoring/`），产品层（`services/api/app`）只保留薄路由挂载（目标 ≤500 行）。禁止在 `main.py` 内继续堆积医学监查逻辑——这是 §18"不把巨型 main.py 当作新控制图"的落地口径。
- 前端医学监查功能收敛为单代 feature 目录，不允许多代（r5/r7/g6）并存。

## 修订 2：§17 专业使用完成门（替换）

原"五项目 × 双角色 × 连续两轮零开放 P0-P4 ＋ clean-streak 重置"废止。新完成门：

- 五个真实项目（MG-K10-SAR、芦可替尼 AD、MY008-3-02、MY008-3-01、MY009-UC-2-01）每项至少一次真实全量 Run；存在真实兼容双快照时追加一次增量 Run。
- 用户本人按预先写好的验收清单逐项确认（风险定位、来源下钻、Profile/Timeline、漏报对照、Query 草稿、报告审阅）。
- P0-P4 严重度语义（§17.1）保留为缺陷分级语言；发现缺陷即修复并回归受影响范围，但不设 clean-streak 连续轮次机制。
- 原始项目资料只读、输出隔离的要求不变。

## 修订 3：真实数据与真实模型的进入时机（新增，废止相关旧约束）

- 原 R8 G0–G8 门序及"G7 前禁读真实项目、G8 前真实项目语义不进入模型、G6 前不启动产品浏览器"等约束全部废止（用户确认这些是实施过程自设的，非用户要求）。
- 新口径：真实项目的**只读隔离副本**可在整合完成后（实施计划 v2.0 阶段 C）立即进入确定性解析层，并可按用户配置进入模型做语义 mapping 和医学解构。
- §19.1 反过拟合红线不变：真实资料是泛化挑战与来源证据，不是产品常量库；项目专有列名、药物、量表、风险模式不得写入公共内核。

## 修订 4：§9 多模型机制默认值（收紧默认，机制保留）

- `ensemble_size` 默认 1。多模型并行、归并、独立 adjudication binding 的设计合同保留，作为用户可选配置，**不作为任何阶段门禁**。
- 单执行者路径下保留确定性 evidence_verifier；`needs_user_attention` 语义不变。

## 修订 5：§12 视觉与进度验收边界（放宽）

- 视觉验收以用户主力分辨率一档为准，关键页截图存档；原 1920×1080–4K 三视口/多视口矩阵门废止。
- 真实 manifest 进度、结构化播报、不显示假进度等要求不变。

## 修订 6：§15.4 与通知的验证方式（降级验收，功能不变）

- 备份、恢复、导出导入、迁移功能保留（R7 slice-09A/09B 已实现），真实验证改为：在真实项目数据落地后做一次完整备份→恢复→校验演练。
- 本地通知功能保留，验收改为真实使用中的一次手动确认。围绕两者的合成验收编排（十三项应用内任务状态机、九终态×四能力矩阵、双通道 presented 验收、六类失效导航、独立 observers/reconciliation）全部废止。

## 修订 7：§21 工程管理标准（新增章节）

1. **git 是唯一版本与完整性权威。** 冻结哈希手账、markdown 恢复锚点、digest 刷新工序全部由 commit + tag 替代。工作树必须始终可从 git 历史重建。
2. **Trellis 管理项目文件。** 任务 PRD 与状态在 `.trellis/tasks/`，日常工程记录在 `.trellis/workspace/` journal，稳定工程标准在 `.trellis/spec/`。`context/` 与 `reviews/` 不再新增过程记录，只读留档。
3. **Ponytail 代码约束**：单文件指导线 ≤800 行、硬上限 1500 行；不为单次使用写抽象；fixture 数据超过 200 行必须外置为数据文件（JSON 等），不得内嵌 Python 字面量；能复用现有 helper 就不新写。
4. **测试策略**：行为断言优先。禁止新增冻结哈希 pinning 测试；optimizer/hash-seed 矩阵（normal/-O/-OO × 多 seed）不作为门禁；合成 case 矩阵不追求数量，新功能验证优先级为真实数据抽查 ＞ 代表性合成行为测试 ＞ 批量生成矩阵。
5. **治理**：阶段内 Codex 自验＋聚焦测试；阶段边界一次独立 fresh-context 评审＋用户确认。不做 per-slice 合同冻结与多轮多模型会商。外部 harness 会话是易失资源，任何工程状态不得依赖"续接同一 session"。

- 废止：P0-P4 最终验收矩阵 ADR（随 §17 修订简化）。
