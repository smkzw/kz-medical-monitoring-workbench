# R7 Slice-08 三模式跨 Run 连续性合同 v0.1

日期：2026-08-29  
状态：`SUPERSEDED_BY_V0_2_AFTER_CONFERENCE_REVISE`

## 1. 目标

在不运行真实项目、不新增医学权威的前提下，把同项目已发布运行之间的比较基线、医学决定版本、风险生命周期、R6 模式输出和可复用产物连接成一个可恢复、可解释、可确定性重放的产品事实面。

## 2. 权威边界

1. 当前完整快照、已发布比较运行、规则版本、ExecutionProfile、manifest、R6 receipts 和 R5 authority packet 均为显式输入；R7 不重算医学事实。
2. `DecisionBaseline` 只引用已发布且身份闭合的结果；未发布、失败、跨项目、错误模式或来源不完整的运行不得成为基线。
3. `CarryForwardPlan` 是逐对象处置清单，不是复制整个旧结果。每项必须记录来源运行、来源对象、目标对象、兼容性、原因、证据摘要和处置。
4. `RiskTransition` 只描述同一稳定风险身份在两次已发布结果间的状态变化；不把相似文本自动合并为同一风险。
5. R5/R6 继续拥有医学输出和看板权威；R7 只拥有运行间绑定、连续性计划和公开中文投影。

## 3. 核心对象

### 3.1 DecisionBaseline

至少包含：项目、模式、来源运行/快照/截止点/规则集合/决定版本、目标运行/快照/截止点/规则集合、R5 authority digest、R6 publication/receipt digest、创建时间和不可变内容摘要。

### 3.2 CarryForwardPlan

每个条目固定为以下处置之一：

- `reuse_unchanged`：事实与适用规则未变化，且可复用产物摘要完整；
- `re_evaluate_changed_data`：相关数据新增、修订、删除或无法逐项比较；
- `re_evaluate_rule_change`：适用规则版本改变；
- `re_evaluate_prior_uncertain`：上一轮为不可评估、证据不足或待核实；
- `close_with_evidence`：本轮证据支持不再开放，但不得覆盖上一轮历史；
- `blocked_incompatible`：身份、模式、截止点、来源或产物不兼容，禁止沿用。

`reuse_unchanged` 必须携带上一轮可复用 artifact digest，并在本轮重新核对对象身份、当前适用性和摘要内容；没有显式复核不得标记为已完成。

### 3.3 RiskTransition

公开变化仅允许：`新增`、`升级`、`持续`、`降级`、`关闭`、`重开`、`需重新判断`。状态变化必须绑定稳定 risk identity、前后严重度/状态、原因类别与来源证据；无法确认同一身份时建立新风险并标记“需重新判断”，不得静默续接。

## 4. 三模式规则

### 4.1 日常监查

- 默认使用最近一次已发布的同项目日常结果；用户可选择其他合格基线。
- 输入仍是当前完整 listing；canonical row-level diff 只决定复核范围，不删除既往上下文。
- 新增/修订/删除/不可比较记录及受其影响的关联对象必须重新评估。

### 4.2 锁库前监查

- 可对同项目已发布锁库前结果做多轮全量比较。
- 只有显式 Query/修订关联证据才能显示“Query 后修订影响”；其他变化显示“本轮数据修订变化”。
- 已关闭风险若相关事实再次变化，应进入“重开”或“需重新判断”，不得继续沿用关闭结论。

### 4.3 锁库后—CFDI 核查前

- 每个运行固定项目、快照、截止点、中心覆盖、规则集合和决定版本。
- 同一固定总量运行只允许确定性重放；任何数据或规则改变均创建新运行。
- 旧运行、旧看板、旧 Journey 和来源证据不得被新运行覆盖。

## 5. 原子发布与恢复

1. 连续性计划先在 run-keyed staging 状态生成并完整校验；再绑定 R5 authority/R6 receipt；最后与 ResultPublication 同一事务或可证明等价的 CAS 门推进为 `available`。
2. 中断后按同一 idempotency key 重建相同摘要；同 key 不同内容冲突。
3. 迟到回调、旧基线、旧规则或旧 manifest 不得覆盖已发布事实。
4. 部分 plan、缺失条目、摘要不一致、artifact 损坏或状态转移不合法时结果入口保持关闭。

## 6. 用户投影

- 项目/中心默认看板优先展示中高风险的新增、升级、持续和需重新判断项，以及本轮变化受试者数。
- 风险 Inspector 显示“上次结论—本次变化—判定依据”，使用中文业务词，不显示 run、digest、CAS、artifact、provider、model 等内部词。
- Patient Journey 在同一访视轴标记本轮新事件、修订事件和风险变化；点击可查看本轮来源和上一轮比较来源。
- 核查前固定总量明确显示“本次固定数据范围”；新运行不覆盖旧看板。

## 7. 最小验证矩阵

1. 三模式各自正确基线；跨项目、跨模式、未发布、失败和来源不完整基线全部阻断。
2. 数据新增/修订/删除/不变/不可比较，以及规则新增/取消/改版的逐对象处置。
3. `reuse_unchanged` 缺 artifact、身份变化、适用性变化或摘要篡改时阻断。
4. 风险新增/升级/持续/降级/关闭/重开/需重新判断；相似文本不同身份不得合并。
5. Query 归因有证据/无证据两条路径。
6. 固定总量同请求重放、数据或规则改变创建新运行、旧结果不变。
7. staging 前后、R5 绑定前后、发布 CAS 前后的故障注入与恢复。
8. 跨 `PYTHONHASHSEED`、关闭重开 SQLite、重复请求和迟到回调的确定性。
9. 项目、中心、受试者和来源页面使用同一前后运行身份；越界或不一致整页失败关闭。
10. ego(lite) 1280/1440/1920 验证中文层级、风险变化、来源比较、访视轴和无页级横向溢出。
