# R7 Slice-09E 本地分发与数据处置合同 v0.2

日期：2026-08-31  
状态：`REVISED_FOR_SAME_SESSION_ACCEPTANCE`

## 1. 目标

在不改动医学写作子系统、不启动真实服务、不读取真实项目的前提下，为医学监查子系统建立可验证的本地应用交付边界：中文的一键启停/状态入口、首次启动检查、升级前保护、失败回滚说明和卸载数据处置。

## 2. 允许路径

- `deploy/medical_monitoring_local/**`
- `tests/test_medical_monitoring_local_distribution.py`
- 与本合同、执行和接受直接相关的 `context/**`、`reviews/**`、`artifacts/**`、`runs/**`
- 只有在无法复用 09A/09B/09C 公共接口时，才可对医学监查 R7 专属模块作最小接线；不得改动医学写作模块或其分发目录。

## 3. 必须实现

### 3.1 中文入口与端口归属

单一管理脚本提供 `start / stop / status / preflight / prepare-upgrade / uninstall-plan`。普通用户可见输出只使用“医学监查工作台、启动、停止、运行状态、升级准备、保留项目数据、清除项目数据”等中文表达；`--help` 与失败提示也使用中文。

端口合同固定为：8911 为后端、5174 为桌面前端开发运行入口、8984 为医学监查辅助运行入口。状态检查可读取三者；停止动作只允许终止工作目录属于当前医学监查分发根或其 `frontend` 的 listener。任一端口被其他应用占用时拒绝启动且不得终止对方进程。端口、数据库、进程、表名和绝对路径只进入机器证据或故障详情，不进入普通成功文案。

### 3.2 首次启动

`preflight` 只检查既有 Python/Node、前端依赖、运行配置、可写数据目录和端口占用；任一缺失均失败关闭并给出一条可执行的中文修复提示。检查不得调用模型、创建真实项目或启动服务。

### 3.3 升级准备

`prepare-upgrade` 必须先使用 09A 的项目备份/清单语义生成升级保护证据，再调用 09B 兼容性预检；任一步失败都不得推进版本标记、schema 或改写原数据。09B 拒绝时保留已成功完成的 09A 备份与摘要供恢复，原子删除未完成 staging，并显示“已阻止升级，项目数据未更改，升级保护备份已保留”。

同一项目的 `prepare-upgrade` 必须复用 09A 项目维护门，单写者运行；并发第二次调用返回稳定冲突结果，不创建第二份 staging。`preflight/status` 可并发只读。

### 3.4 卸载数据处置

`uninstall-plan` 默认结果必须是“移除应用、保留项目数据、备份、导出与业务审计”。只有显式 `--include-project-data` 才能生成“同时清除项目数据”的预览计划；该命令不删除任何文件，也不得串联删除命令。

预览计划写入调用方显式指定的输出目录；测试默认使用临时目录。JSON 至少包含 schema、处置模式、应用对象、保留对象、拟清除对象、生成时间、根身份摘要与清单 SHA-256。真正删除属于未来独立、用户再次确认的工具，不在 09E 范围。

### 3.5 发布清单

构建器只生成医学监查分发源文件清单、字节数、SHA-256、运行前置条件和范围声明。该清单独立于 09A `.mmbackup`；只引用 09A 工作区/备份身份摘要，不复制备份实现。它不得把凭据、真实项目数据、缓存、日志、数据库、历史测试输出或 `deploy/medical_writing_local` 收入医学监查分发清单。

## 4. 不变量

- 默认数据处置永远保留项目数据、备份、导出与业务审计。
- 未通过首次启动检查不得产生“已安装/已就绪”状态。
- 升级准备失败不改变原数据、schema 版本或当前可运行版本。
- 09A/09B/09C 是唯一备份、迁移、审计语义来源；09E 不复制第二套机制。
- 任何路径与项目身份必须来自配置/manifest，不硬编码真实研究、药物、疾病、评分或 listing 格式。
- 受控验收入口只接受临时 synthetic 工作区；非临时或真实项目根在验收 runner 中失败关闭。产品入口不据此声称已验证真实项目。
- 09E 不安装 launchd、系统服务或需要管理员权限的组件。
- 合同审阅与离线验收期间 8911/5174/8984 全程无监听。

## 5. 命令结果

| 退出码 | 含义 |
|---|---|
| 0 | 检查或计划生成成功 |
| 2 | 首次启动条件缺失或参数不完整 |
| 3 | 端口被非本应用占用或停止对象不归本应用 |
| 4 | 备份、兼容性或升级准备失败，原数据未更改 |
| 5 | 同项目维护任务正在执行，本次调用未开始 |

`uninstall-plan --include-project-data` 成功生成预览仍返回 0；用户可见文案必须明确“尚未删除任何数据”。

## 6. 验证矩阵

| 场景 | 预期 |
|---|---|
| 完整依赖与配置 | preflight 返回可启动，不启动服务 |
| Python/Node/配置/目录任一缺失 | 中文失败关闭，无副作用 |
| 8911/5174/8984 任一端口被非本应用占用 | 拒绝启动，不终止外部进程 |
| synthetic 升级准备成功 | 备份与兼容性证据齐全，原工作区不变 |
| 备份失败 | 不生成升级状态，不改原数据 |
| 兼容性预检失败 | 保留成功备份、删除未完成 staging，不改原数据 |
| 同项目并发升级准备 | 第二次稳定冲突，无第二 staging |
| 默认卸载计划 | 保留项目数据、备份、导出与业务审计 |
| 显式数据清除计划 | 生成带 SHA-256 的 JSON 预览，仍不删除 |
| 发布清单 | 无凭据、真实项目、缓存、日志、数据库、医学写作分发文件 |
| 非临时/真实项目根进入验收 runner | 失败关闭，不读取内容 |
| 重复执行 | 输出业务内容稳定、无额外副作用；时间与输出路径不参与业务摘要 |

至少在 `normal/-O/-OO` 与三个 `PYTHONHASHSEED` 下验证清单和处置计划确定性；聚焦测试与 R7 相邻回归必须通过。
