# 医学监查交互式受试者医学旅程调研与设计决策

日期：2026-08-09  
状态：外部方案扫描、本地 Slice 4 验证与用户术语纠偏已完成；作为 R3-R5 视觉合同持续生效  
适用范围：医学监查子系统的受试者级投影，不改变 canonical fact、风险身份、原始来源或现有 Run 权威

## 1. 结论

最终可以、也应当形成一个交互式“受试者医学旅程”面板。它不是把现有 Patient Profile 和 Subject Timeline 机械拼接，也不是患者招募/依从性语境中的 patient journey，而是研究内受试者的纵向医学监查工作面：以同一条 `SubjectTemporalSpine` 为时间与访视权威，把医学趋势、事件关系、风险提示和来源证据同步投影到一个可缩放、可筛选、可回跳的视图中。

产品结构采用“统一外壳＋同步子视图”，保留 Profile 与 Timeline 的专业职责：

- `旅程总览`：共享访视轴、阶段带、事件泳道和风险标记，默认入口；
- `指标趋势`：原 Patient Profile 的分领域趋势、小多图和医学摘要，横轴与旅程总览同步；
- `事件明细`：原 Subject Timeline 的点事件、区间事件、重叠和顺序，横轴与旅程总览同步；
- `风险证据`：风险正反证、来源、Query 草稿和历史，不建立待办或强制人工处置流程。

这样既保留完整 Profile/Timeline，又让懒惰、视觉敏感、风险敏感的资深医学监察员首先看到“何时、哪次访视、发生了什么、风险在哪里、依据是什么”。前台不得出现“正式事实”“候选信号”“只读投影”“attempt/provider/model/backend”等研发或数据治理词；它们如需存在，只能留在内部合同与审计层。

## 3. 本地基座复盘

现有 R1 Slice 4 已证明共享访视轴、Profile/Timeline 同步视窗、风险—依据回跳、点/区间事件和离线双浏览器可行；AE、MH、CM、IP、检验/检查、住院/操作、症状/体征已分别使用不同事件与风险标记，不再混成“已记录事项”或一个通用风险点。领域数据无需推倒重来。

仍需在 R3-R5 补齐的是规模、自适应和层级联动：

1. 把当前合成域扩展到疗效/PRO/PK、PD、入排标准、禁用药、访视/给药偏离等真实监查域；
2. 从 Study Knowledge Pack 和异构 listing mapping 自适应生成泳道，不允许针对某一项目硬编码；
3. 建立项目/中心异常到受试者、时间窗、事件、风险依据、原始 listing 行的连续深链与返回上下文；
4. 在数百/数千事件和多指标趋势下验证语义缩放、轨道折叠、聚合与性能；
5. 将增量新增/修改/撤回/补录与既往快照差异叠加到同一旅程，但不把浏览行为写成医学处置。

过去 `subject-timeline-builder` 与 `clinical-patient-profile-html` 产物中的横向日期轴、简短访视标签、AE/给药/合并用药/实验室泳道和指标趋势小多图继续作为视觉参考；旧产物不能成为事实权威，且其分屏和长列表需要被统一旅程交互吸收。

## 4. Patient Journey 投影合同

### 4.1 共享坐标

- 默认坐标为实际日期连续轴；研究日是同一事件的派生标签，可切换显示；名义访视只作为锚点/参考带，不能改写真实发生日期。
- 顶部固定显示研究阶段带、截止点和访视节点。访视节点区分名义、实际和非计划访视；非计划访视按真实日期进入受试者轴。
- 视窗状态由 `project_id + run_id + snapshot_id + subject_id + spine_id + axis_mode + start + end + selected_event/risk` 唯一表达；Profile、Timeline、风险和来源抽屉共享该状态。
- 日期缺失、部分日期、日期冲突和访视归属不确定不能被强制安放；进入独立“日期待定”区域并保留不确定性。

### 4.2 泳道与指标

默认轨道按临床语义明确分开，绝不使用“已记录事项”统称：

1. `AE`：AE/SAE/AESI 的发生、加重、转归、严重性和处理；
2. `MH`：既往/现病史的起止、活动性及与当前事件的关系；
3. `CM`：合并用药/治疗的开始、停用、剂量/频次变化，突出禁用药和治疗 AE 的用药；
4. `IP 给药`：暴露、给药、剂量调整、中断、漏用、停药与重新给药；
5. `检验与检查`：实验室、生命体征、ECG、影像及其他检查的趋势与异常点；
6. `住院与操作`：住院、急诊、手术/操作和关键诊疗行为；
7. `症状与疗效`：症状/体征、量表、PRO、疗效终点、PK/生物标志物；
8. `方案符合性`：入排标准、禁用药、访视窗、给药、样本/评估等 PD 线索。

轨道是否显示由方案与数据自适应决定；不适用的轨道可隐藏，但必须能解释“本研究不适用”或“本次数据未提供”，不能用空白冒充无风险。

Timeline 负责点/区间事件及重叠关系；Profile 的趋势图以相同 x 比例尺放在对应领域下方。用户缩放、拖拽时间窗、选择访视或点击事件时，所有可见子视图同步。

### 4.3 风险覆盖层

- 风险标记锚定到事件、区间或访视位置；跨时段风险使用带端点的区间覆盖，不把起止不明伪装成精确区间。
- 前台形状首先表达临床域：AE、MH、CM、IP、检验/检查、住院/操作、症状/疗效、方案符合性各自有稳定图标/轮廓和直接文字；风险叠加层同时显示域、风险类型与等级，如“AE漏报·中”“禁用药偏离·高”“入排不符合·高”。禁止“正式事实”“候选信号”“通用风险点”等标签。
- 已录入数据与疑似漏报/不一致用医学原生短语区分，例如“已记录 AE”“疑似 AE 漏报”“已记录 MH”“疑似既往史未录入”“合并用药”“禁用药相关偏离”；不得让用户理解内部对象生命周期后才能读图。
- 中高风险全部优先显示，不人为限制 3-5 项；低风险可按泳道聚合。重叠标记聚成数量簇，展开后仍保留各自身份。
- 点击标记先出现轻量摘要，再打开证据抽屉；抽屉包含依据、发现、行动项、正反证、来源定位、风险历史和关联 Query。
- 风险卡、标记、Profile 异常点、Timeline 事件和原始 listing 行双向高亮；从项目/中心看板下钻时直接落到受试者、相应时间窗和选中风险。
- 风险被筛选或移出当前时间窗时，不自动关闭抽屉或改变风险生命周期；页面明确显示当前筛选/时间窗。
- 颜色只辅助严重程度。域名短标签、形状、描边/线型和直接文字至少提供一种非颜色冗余编码，符合 [Section 508/WCAG 色彩原则](https://www.section508.gov/create/making-color-usage-accessible/)；任何风险都能用键盘到达并打开同一证据抽屉。

### 4.4 视觉与信息密度

- 首屏只保留受试者身份/分组/当前阶段、共享访视轴、中高风险与关键治疗关系；辅助字段在悬停、焦点或证据抽屉中展开。
- 视觉高级感来自稳定网格、克制留白、清晰字号层级、同域一致编码、细腻但低干扰的阶段带和选中态；不使用玻璃拟态、夸张渐变、持续动画或大面积警报红。
- 缩放采用语义级别：研究全程显示阶段/访视/中高风险；中尺度展开区间事件与关键趋势；近尺度显示日期、数值、单位和来源入口。缩放不能改变医学含义或隐藏高风险。
- 右侧证据抽屉与主轴保持同步，默认呈现“为什么提醒—发现了什么—建议核实什么—来自哪里”；Query 草稿仍按“依据＋发现＋行动项”三分句生成，但不是待办系统。

### 4.5 增量与身份

- 全量首次运行生成完整 Journey 投影；后续全量快照增量比较只重建受影响受试者，但界面始终可查看当前全量。
- 新增、修改、撤回、补录和风险变化作为快照差异叠加，不复制或覆盖原始临床记录；补录 AE/MH 后保留“原疑似漏报—后续已补录记录”的匹配历史。
- 同一受试者在 mapping/identity 有歧义时 fail-closed，不把不同身份拼成一条旅程。

## 5. 技术决策

R1 不直接引入外部时间轴产品或并行 R/Shiny 运行时。当前已通过的 Slice 4 是离线、无远程依赖、原生 JavaScript/CSS 的只读工作台，仅用于证明交互合同；它只消费 `SubjectTemporalSpine`、领域事件、风险和来源定位。

这不是永久拒绝可视化库。R3/R5 在真实结构但隔离的规模基准中，若数百到数千事件、数十指标的小多图导致自研投影难以满足性能或可访问性，再分别评估：`vis-timeline`（Apache-2.0 OR MIT）承担点/区间和分组时间轴，Apache ECharts（Apache-2.0）承担趋势/项目/中心图。二者均须经过版本锁定、离线打包、可访问性、性能、安全和迁移门；任何库只能替换投影实现，不能成为领域事件、风险或时间身份权威。

回滚路径：移除 Journey 投影后仍可由 `SubjectTemporalSpine` 恢复 Profile/Timeline 只读视图；不迁移 canonical facts，不改变风险生命周期。

## 7. 验收门

1. Profile、Timeline、风险和来源抽屉在同一 `spine_id`、同一实际日期/研究日转换和同一时间窗下结果一致；
2. 任何中高风险从项目/中心层最多一次下钻进入正确受试者、时间窗和风险标记，再一次操作到原始来源；
3. 名义访视、实际访视、非计划访视、访视间事件、部分/冲突日期均不被错误吸附；
4. AE/MH/CM/IP/检查/住院/症状/疗效/方案符合性及各自风险不只靠颜色区分，键盘/焦点/降低动态效果可用；
5. 高密度时默认仍能在首屏识别中高风险和关键治疗/事件关系；
6. 不显示后端字段、内部状态码、英文调试标签、强行翻译式中文，尤其禁止“正式事实”“候选信号”“只读xx”“attempt/provider/model/backend”；
7. 视图只读，不把点击、筛选或浏览行为误写为医学确认或风险处置。
