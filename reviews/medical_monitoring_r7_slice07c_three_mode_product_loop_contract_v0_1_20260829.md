# R7 Slice-07C 三模式产品闭环合同 v0.1

日期：2026-08-29  
状态：`SUPERSEDED_BY_V0_2_CORRECTIVE_APPENDIX`

## 1. 用户目标

资深医学监察员进入一个项目后，不需要理解 run、snapshot、manifest、provider 或内部工作项。
用户只需选择本次监查目的、当前数据批次和必要的既往监查批次；如有项目特殊关注点，可用
自然语言补充。确认后系统在后台完成监查，用户可离开页面；再次进入时能看到真实进度，完成
后直接进入同一批次的项目/中心看板，并从风险或流向逐例进入 Patient Journey。

本切不声称医学结果已经达到真实项目质量。它只把已接受的 R7 运行身份、后台进度和 R5
只读结果表面串成一条合成数据产品路径，并关闭“进度已完成但看板仍显示另一批次”的身份缺口。

## 2. 三种业务模式与用户语言

主入口只显示三张中文模式卡：

1. **日常监查**：默认“仅分析本次新增或修订的数据”；首次运行或用户明确选择时可做“重新
   全面分析”。数据文件即使是完整导出的全量 listing，也不能因此把业务含义误写成全量运行。
2. **锁库前监查**：以当前完整数据做全面复核；若用户选择上一轮锁库前监查，则同时突出本轮
   Query 后修订影响。底层仍按全量数据运行，但看板必须明确“全面复核 + 修订变化”，不得把
   修订变化误称为只分析差异行。
3. **核查前监查**：使用锁定的固定总量形成最终全量项目报告、中心/受试者风险集中视图和现场
   自查清单。数据范围一经首次开始即冻结；不得在原运行上静默替换。

内部 `daily | pre_lock | post_lock_pre_cfdi` 和 `full | incremental` 只用于合同与 API；主界面
使用上述中文。日常增量必须选择一个已接受的同项目既往快照；锁库前修订复核选择同项目既往
锁库前运行作为比较基线，但 execution basis 仍为 full；核查前只允许 full。

## 3. 一次监查的最少步骤

### 3.1 入口

项目/中心默认看板顶部只提供一个主动作“开始一次监查”和一个次入口“查看历次监查”。如果
当前运行正在进行，主动作改为“查看本次进度”；如果已完成，显示“查看本次结果”，不叠加第二
个重复入口。

### 3.2 四步向导

1. **选择监查目的**：三张模式卡，默认推荐上次同项目采用的模式，但必须显示推荐理由。
2. **选择数据与比较范围**：从服务器给出的可用批次中选择当前批次；只有合同允许时才显示
   既往批次。不得要求用户输入内部 ID。每项显示数据截止日期、导入时间、数据范围说明和能否
   比较；缺少合格基线时禁用相应方案并用中文解释。
3. **补充特殊关注点**：可空的自然语言文本。系统先拆成结构化规则草案，展示“关注对象、
   判断条件、适用范围、从哪一次监查开始”；用户只确认本次采用。新增规则只影响本次及之后
   明确选择它的运行，不回写历史结果，也不直接形成医学结论。
4. **确认并开始**：用一页摘要复述模式、当前数据、比较基线、特殊关注点和后台运行说明。
   点击一次后由服务端原子完成绑定、工作范围准备和开始；重复提交返回同一运行，不创建两次。

模型/调用配置放在折叠的“高级设置”中。默认配置为
`mtplx/Youssofal--Qwen3.8-27B-MTPLX-Optimized-Quality:medium`；显式可选
`deepseek/DeepSeek V4 flash:max`。主向导不显示 provider、selector、attempt、timeout 等词。
本地 MTPLX 使用长任务等待语义，不能因短时无输出就显示失败；只有受治理的终端失败才进入
失败态。

## 4. 服务端权威接口

沿用项目级前缀 `/api/projects/{project_id}/modules/medical-monitoring/r7`，新增最小产品表面：

- `GET /run-setup/options`：返回模式卡、可用数据批次、合格既往运行/快照、默认选择及中文原因。
  所有 option 都绑定 canonical project；不得返回路径、哈希、数据库、模型内部身份或原始 ID。
- `POST /risk-rules/preview`：把自然语言关注点解析为结构化草案。v0.1 synthetic 实现可用确定性
  parser，但响应必须显式标记为“待确认的关注规则”，不得冒充已执行风险判定。
- `POST /runs/prepare-and-start`：接收 option token、已确认规则草案与 idempotency key；服务端
  解析 token 后原子绑定 Run、生成模式工作范围、准备并开始后台执行。客户端不得提交 work-unit、
  profile、模型、source revision 或内部图身份。
- `GET /runs`：返回同项目有界历史列表，包含中文模式、数据截止点、比较范围、运行状态、结果
  是否可打开；不暴露内部 ID，但提供不可解释的 opaque navigation token。
- `GET /runs/{public_run_token}/result-entry`：只有完成且结果发布成功时返回 R5 canonical route
  所需的 project/run/snapshot/cutoff；失败、未完成、取消、身份不一致或发布缺失均 fail closed。

现有 bootstrap/profile/run/prepare/start/progress 路由继续作为底层管理表面；本切不得让普通
用户通过前端直接拼接这些内部步骤。`prepare-and-start` 必须有事务/补偿语义：若 start 未获得
后台所有权，运行保留为可恢复状态并返回同一 public token，不得再创建一个 Run。

## 5. 模式工作范围

服务端从冻结的三模式图模板生成受众可读工作范围，而不是由浏览器发送：

- 共用：资料与方案控制点、数据结构/完整性、Patient Journey、AE/MH/CM/IP/PD/入排/检验检查
  多维风险、项目/中心汇总、全流程 QC。
- 日常：新增/修订数据逻辑与科学性核查、风险/疗效/安全性趋势变化、结构化 Query 草稿。
- 锁库前：当前全量风险、Query 后修订影响、多轮未关闭问题、锁库前核查包。
- 核查前：固定总量全量报告、中心/受试者风险集中视图、现场自查 checklist、外部报告审阅。

每个模板版本冻结进 Run；同一模板和输入重放不改变分母。模板演进创建新的范围版本；核查前
首次开始后禁止在原 Run 上改变。特殊规则草案只生成附加检查工作项与版本引用，不改写主模板。

## 6. 结果发布与看板身份

后台运行“完成”与“可查看结果”是两个相邻但不同的事实。只有全部必要工作项达到允许终态、
R6 输出 envelope 通过身份/覆盖/QC、R5 authority packet 成功发布并绑定同一
`project × run × snapshot × cutoff` 后，`result-entry` 才可打开。

- 进度完成但发布失败：显示“分析已结束，结果整理未完成”，保留恢复入口，不回退到上一次看板。
- 切换项目或运行：所有迟到响应丢弃；看板、流向、风险、中心和 Journey 必须同时切换身份。
- 从结果返回历次监查：保持当前项目与运行；选择另一运行后整页原子切换，不混用前后批次。
- R5 `subject_flow`、风险变化和 Journey 只能读取该发布包；不得从进度文本或运行状态推断结果。

## 7. 前端状态与体验

向导状态仅为：读取可用范围、填写、规则预览、确认、正在创建、已进入后台、创建未完成。
不得展示原始异常、技术日志或模型调用状态。提交后立即进入已接受的 R7 进度面板；用户离页或
关闭浏览器不取消后台任务。刷新以 public token 恢复；进度完成且 result-entry 可用时主按钮
变为“查看本次结果”。

桌面宽屏优先，主操作与监查范围摘要在 1280×800 首屏可见。模式卡和数据批次使用清晰的
单选，不用下拉框堆叠内部值。危险或不可逆含义只在核查前范围冻结处做一次清楚确认，不把系统
做成待办工具。

## 8. 失败关闭与重放

1. option token 过期、跨项目、当前数据变更或既往基线不再合格：提交前重新读取并要求用户
   确认，不猜测替代项。
2. 相同 idempotency key + 相同规范请求：返回同一 public run；同 key 不同请求：409 中文冲突。
3. 浏览器超时不能证明服务端失败；先按 token 查询已有运行，再决定是否重试。
4. MTPLX 长时间无新文本但租约/心跳有效：继续显示当前工作和已用时间，不转失败。
5. 任何内部账本、结果包或身份对账失败：不展示部分看板，不使用上次结果填充。

## 9. Synthetic 验收矩阵

至少覆盖：

- 首次日常全量；日常使用完整导出 listing 的增量；日常无合格基线；
- 锁库前首次全面复核；同完整 listing 修订后的比较复核；
- 核查前固定总量首次运行、重复开始、范围变更拒绝；
- 特殊关注点为空、可解析、歧义、运行后新增且历史不变；
- 双击提交、网络超时后重入、跨项目 token、项目切换迟到响应；
- 后台离页、刷新恢复、停止/继续、执行完成但发布失败、发布恢复、最终看板/中心/Journey
  身份一致；
- 默认 MTPLX 与显式 DeepSeek 选择合同；MTPLX 长等待不误判失败；
- 1280/1440/1920 ego(lite) 中文、键盘、视觉层级和零横向溢出。

## 10. 本切边界与完成门

只使用 synthetic 数据与隔离端口；不启动 8911，不读取或运行五个真实项目，不修改医学写作
子系统，不设计或测试安全功能。v0.1 合同独立会商通过后才实施。

完成需要：后端/前端确定性回归、三模式 synthetic 端到端、ego(lite) 真实操作、独立视觉会商、
Codex 重新打开最终界面、运行/结果身份对账、临时服务停止和接受记录。即使全部通过，也只接受
Slice-07C synthetic 产品闭环，不等于真实医学质量、R7 总体或 R8。
