Authority invariants:
1. The authoritative StudyDefinition identity is the complete triple
   `(id, revision, sha256)` on the current canonical protocol document.
2. When no authoritative StudyDefinition exists, an unbound working copy may
   remain editable. This preserves early/manual editing.
3. Once authority exists, a stored copy is active only when its complete
   StudyDefinition triple exactly matches the current authority.
4. A blank, partial, stale revision/hash, or mismatched triple is quarantined.
5. A quarantined copy is returned separately as `quarantined_blocks`; active
   `content_blocks` come from the authoritative current baseline (or a last
   valid bound copy), never from the quarantined copy.
6. Normal save, AI revision application, table edit, approval, and export
   fail closed while the active section has unresolved quarantine.
7. The user gets two explicit, auditable recovery actions:
   - `accept_and_bind`: deliberately adopt the quarantined blocks under the
     current authority and create a new bound revision.
   - `revert_to_authoritative_baseline`: discard only the quarantined working
     content from the active path, restore current baseline, bind it to current
     authority, and preserve the prior snapshot/audit record.
8. Both recovery actions require expected working-copy revision plus current
   authority identity, are idempotent, reject stale requests, and append an
   audit event. Neither is called "medical approval".
9. A later StudyDefinition revision/hash change quarantines the old bound copy
   until explicit recovery; no silent text migration.
