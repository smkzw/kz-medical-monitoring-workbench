## 真实用户验收场景
用中文医学监查角色从完整资料创建研究，无CLI修库、无开发者补医学答案：
1. 添加资料，查看自动理解范围、少量有依据的真歧义；离开/返回/暂停恢复。
2. 从研究/中心看板找到重点，查看流向分母，打开任一受试者真实时间八轨和正常数据。
3. 从某个风险进入精确事件（至少第二AE与无AE的LB各一），打开原始记录/条款，返回保持筛选。
4. 对比一次兼容增量，解释新/改/消失/不可比和零变化，确认未把缺资料说成无风险。
5. 编辑保存Query草稿并导出，生成研究/中心/个例报告和自查包；不发送或逐风险审批。
6. 800+发现搜索/筛选/阅读长否定句、快速切项目/快照、复制链接重开；浏览记录0模型调用。
7. 恢复到隔离目录后相同结果、来源与草稿可查。

## 性能目标与测量
以下是本计划新增的工程验收目标，不是假称已有SLA/实测：
- 既有结果热切换/筛选/详情在当前目标Mac上P95≤1秒，冷进入单个冻结研究结果P95≤3秒（不含初次模型分析）。
- 800+条发现、完整长文详情、1440/1920宽屏不丢数据、持续交互不阻塞；正常浏览0模型请求。
- 原始文件大数据导入3秒内给可见进度/阶段，长模型任务立即可返回稍后查看，不伪造进度。
- 全量导入/双模型吞吐不预设不现实固定秒数；报告实际数据规模、硬件、冷/热、样本量、耗时、内存、请求/token可得值，并与同基线对比。若交互目标受硬件或源规模影响，提供测量和最小优化/用户可理解替代，不静默改成通过。
优先消除每人全表hash/轮询重读/800卡片渲染；有测量后再优化。测试样本足够报告分位，不把单次耗时称P95。
