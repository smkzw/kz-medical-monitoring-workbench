日期：2026-09-06。状态：接管审阅后的实施设计；不是已实现说明或用户验收结论。

本文件完整汇总当前产品合同，替代旧v1.1正文＋v1.2差量作为后续设计入口。旧文档保留为历史，不继续追加过程记录。最新用户指令始终优先。审阅证据见 `.trellis/workspace/宋旻恺/MM_ENGINEERING_REVIEW_20260905.md`；具体步骤见 `.trellis/tasks/09-06-mm-product-rebaseline/implement.md`。

## 1. 产品目标与边界

本地单用户医学经理工作台中的医学监查子系统。用户是中文原生、资深、视觉/数据/风险敏感、不熟悉计算机和AI、不愿做机械核对的医学监察员。系统主动整理与分析，用户看风险、查来源、确认真正需要医学裁决的少量事项。

交付三个完整工作场景：日常定期增量；锁库前全量及Query修订后的增量；锁库后至CFDI核查前固定版本总量、全量报告和现场自查包。层级贯通研究→中心→受试者→事件→源记录→研究资料条款。

不建设独立应用壳、多租户、外部Query发送/回复闭环、正式PD登记/报送、电子签名、额外安全功能或验收专用平行应用。医学写作路由和资产不动。真实原文件只读，分析用隔离副本，输出隔离；历史运行数据和错配证据不删除。不可逆清理另行确认。

不承诺“模型绝无幻觉”；承诺每个结论有来源、覆盖状态、支持与排除依据、适用版本和明确的不确定性，不能把程序通过等同医学真值。

## 2. 用户主流程

唯一首要操作为“添加研究资料”：选listing及方案等文件，系统自动归类、核查研究/版本、展示已读范围，然后后台整理。资料齐备后“开始分析”；无需配置字段名、列码、模型、分片或JSON。

整理页只回答：读到了什么、完成到哪、哪些分析可以进行、还有什么实质缺口。普通明确字段自动接受；技术解析失败由系统补读/重试，不伪装成用户医学问题。真实医学歧义以一个卡片呈现“系统理解／影响／可选解释／相关原文”，可选择暂不判断，仅限制依赖该问题的分析，不清空已有可用结果。

运行可离开页面；提供“暂停整理/继续”“稍后查看”。暂停是持久业务状态，重启应用不自动越过暂停。模型正在返回的结果可完整落盘，暂停后不再领取新任务。界面不假报完成百分比、不滚动模型思考日志。

## 3. 保留架构，补齐业务接线

保留React/Vite、FastAPI、SQLite、内容寻址artifact与现有graph IR。不新增Temporal、第二套agent框架或外部OMP。图控制、持久任务、原始材料和结果拥有明确边界：

| 层 | 唯一职责 | 主要位置 |
|---|---|---|
| 原始来源 | 隔离复制、版本与物理结构、可回看定位 | admission + 现有解析adapter |
| 语义与知识 | 双模型解释、证据补读、研究知识包 | admission/intelligence + 产品内harness |
| 数据 | 映射接受、规范值、事件身份、日期、快照diff | domain/intelligence/admission |
| 控制 | 工作清单、依赖、暂停恢复、重试、成本和真实进度 | graph/runtime + 持久AI repository |
| 医学分析 | AE/MH、CM/IP、PD、疗效、安全、交叉与聚合 | risks |
| 输出 | 风险生命周期、Query、报告、看板与旅程投影 | projections/reports |
| 产品 | 组合根与薄API，单一feature | api + frontend feature |

services中的8601行monitoring_ai_service不得继续长大。按“任务仓储/模型传输/文档理解/字段理解/医学候选/调度”渐进抽取，保留旧导入兼容，不同时重写接口和医学行为。公共写作解析器不修改；监查专属覆盖能力放监查层，通过adapter复用适合的原有读取功能。

迁移完成与真实接通分开验收：现有R4/R5/R6多数为确定性合同、注入输入或离线实现，不能直接称真实运行。真实数据集必须经明确reader/adapter进入SemanticRecord/规则/风险，再由同一批结果构建publication；缺该链时不展示“已可完整监查”。

## 4. 来源、身份和版本

研究ID精确归一化后比对；仅允许声明的标点差异、明确环境后缀或登记别名。禁止任意双向前缀匹配。研究、队列、文档、listing、快照、受试者和中心身份全部绑定。同一药物的不同研究绝不等同。没有研究字段时保留unknown，不能冒称matched；利用方案/eCRF/导出元数据补证据。

来源保存内容版本、物理定位、来源有效期间和适用人群；方案修订按有效时段/中心适用性解释，不一律把最新版本追溯适用于历史全部受试者。IB中的风险知识和研究规定分别建模。只有使用者主动决定才能固定锁库版本或确认真实身份冲突的处置，不能让模型伪造人工确认。

历史错配RUX/MG attempt保持隔离及原证据；正确MG路径与其完全分开。新校验对旧数据只给出重验证结果，不重写旧接受历史。

## 5. 文档和Excel工具能力

内置harness应能请求明确的只读证据工具，而不只是被动接受一个固定prompt。优先现有库/标准库：

- Excel：openpyxl/既有xls parser按物理sheet、行列、合并区、隐藏区、表头、公式及缓存、日期格式、单位、注释、命名表逐项建覆盖索引。全表确定性扫描；格式/公式与显示值分离，缺缓存不猜结果。保留重复列名的物理身份。
- 字段理解：每sheet每列双路完整语义覆盖；全量值分布、同表/跨表关系、罕见值/缺失/单位/日期异常分层样本和原始邻近行上下文。模型可请求更多行、全值域分页、关联候选和某列上下文。不能用首中尾三行证明全列无异常，也不能把“1495列都提交”说成“每个单元格医学含义均确认”。
- PDF：PyMuPDF文字+位置+表格/图片覆盖；混合页、图表、异常字符、疑似扫描正文触发局部OCR/VLM，不能只看整页文字是否为空。正文、脚注、跨页表、分母、页眉版次均有覆盖记录。OCR走已配置gate；失败标明受影响能力。
- Word：OOXML正文、表格、脚注/尾注、文本框、图片、修订和相关部件索引；结构定位与渲染页定位分开。修订接受规则明确；不能把解析器固定page_count=1当真实页数。复杂图表按需渲染/OCR，不把全部Word一律转图片。
- 提供`read_source_region`、`get_column_profile`、`sample_rows`、`search_document`、`read_document_units`、`lookup_standard`等有限工具契约，返回来源revision、定位、覆盖与截断状态。工具不得任意修改数据；读取预算受控，未读完明确partial。

来源引用优先使用工具回执中的原文片段编号，harness从冻结来源回填逐字文本；模型不必抄写长引文。编号必须绑定文件摘要、定位、片段范围及实际读取回执，错误编号或伴随不实引文不能接受。索引检索与字节正文读取分别保留来源类别和覆盖边界。

上述是待实现能力合同，不宣称当前所有工具已有。先接入最小证据补读循环，再扩展格式能力；不为追求工具数量安装大套件。

## 6. MiniMax主分析＋GLM全量盲核对

默认直接API主模型cms-smk/MiniMax-M3（当前已绑定profile，用户cms-router名称作为路由配置别名核实）；核对zhipu-coding-plan/GLM-5.3-flash，高推理。首轮输入同一冻结证据revision，两路上下文隔离；GLM不看主结果。Codex和OMP不在产品运行时参与解释或裁决。

流程：独立初判→覆盖/定位/规则校验→规范化语义比对→只对冲突/缺口请求补证据→匿名再次分析→证据裁决。相同含义的受控别名不制造假冲突；实质差异（原始/编码、治疗身份、单位/日期、对象/时间范围等）完整保留。

自动接受条件：两路完整覆盖、输入一致、引用闭合、语义一致且字段依赖校验通过；或某候选被可复核的确定性证据排除后剩余解释成立。多数票、confidence阈值、主模型身份、没有问号，都不足以自动裁决。二轮仍实质分歧且没有决定性证据时，系统先补读/限定范围；达到有界再审预算后保留不可评估的依赖能力。只有额外医学背景确实能消除歧义才问用户。

### 6.1 显式依赖与说明分离（新合同实施中）

新比较策略只接收两路都显式输出的 `dependency_fields`（domain/source_field定位），旧结果缺少该声明不得默认为无依赖。角色、字段类型、对象身份及其证据字段/绑定、剂量语义、值约束、派生血缘、质量阻断、结构化标准版本和未知新增键保持硬比较；不全量套用旧角色别名库。`related_fields` 在新合同中仅作关联说明，不得用于建立join或替代dependency_fields；两路说明分别保留，不偏向主模型。

仅当 `standards_reference.reference_only` 明确为true时，reference_name/reference_concept/uncertainty三项作为参考说明保存；ctcae_version、grading_definition_version、date_precision等结构化键及未知键仍是硬约束。缺少reference_only声明维持严格比较。说明分歧本身不制造用户问题，依赖一致仍须完整覆盖、真实引用闭合和当前来源校验，不能靠比较器独自生成facts。

新prompt/比较器版本写入job与确认回执；旧默认路径及已接受历史保留。新运行路径禁止依列名或代表值启发式在模型返回后改写量表、治疗或剂量解释；系统只能验证可重放的来源约束、指出缺口并让产品模型补读和修订。启用前以合成反例及隔离真实AE新合同验证，再整合视觉补读。

文档权威选择、字段理解、医学风险发现是不同任务，不能用文档“选对文件”冒充“理解全部条款”。同一协调协议可复用，schema与接受标准按任务独立。mapping阶段不做CTCAE等级、风险或Query结论。

两路远程均确认为当前输入不可用时方可MTPLX Qwen备用；单路失败只修该路，不把本地同模型两次运行称独立双核对。区分传输失败、格式失败、医学不可判定、覆盖不完整；不能把慢任务随意判失败。

## 7. 调度、存储和恢复

按冻结输入revision+阶段+cohort+分片形成幂等work unit；重试同分片，不复制成功分片，不因单个失败重新生成全代。证据变化才产生新代，记录supersedes和实际复用证明。已误建g02先制定恢复计划，只通过repository受控操作隔离/退休未执行重复工作，保留历史，不SQL改状态。

持久pause_requested/paused与lease分离；取消领取、等待在途结果、落盘后停，重启不自动恢复用户暂停。容许过期lease合法回收，不冒充活进程。任务进度GET无创建/重试副作用；后台拥有裁决推进和publication。发布失败可重试，用户离开页不丢结果。

共享冻结证据以内容寻址对象保存；job保存引用和小片段。列表仅查询状态列；执行、接受、恢复边界深校验。不能每次轮询读取数百MB并重新hash。保留已完成证据，成本基线分别测墙钟、输入输出token（可得时）、请求数、峰值内存、artifact体积，不能用字符数替代token。

## 8. 临床语义与知识控制点

知识包由模型从方案、IB/RSI、eCRF、SAP提取，规范为有来源的结构化控制点：适用范围/时段、入排、给药、救援/禁用药、访视窗、样本与终点、AE收集窗、随访、AESI与已知风险、分析人群及缺失数据约定。缺资料只限制相关能力，不凭常识补条款。

CTCAE采用项目规定版本，不自动改到最新版。词条匹配、分级条件、baseline、ULN/LLN、单位、症状/干预条件分别可追踪；条件不足不给确定等级。AE强度/分级、严重性、预期性、因果性、监查优先级分开。实验室异常不自动等于AE、疑似AE/MH不变成原记录；IB有风险不等于该个例因果成立。

AE/MH漏报覆盖症状、用药适应证、检查、住院/操作、给药处置、死亡等线索，并检索已记录AE/MH、时间不相容、替代解释等反证。CM与研究药物/背景治疗严格分开；禁用药与PD依据冻结方案。疗效变化按项目终点及量表规则，不能用安全分级规则代替疗效解释。

每域给适用性、输入覆盖、人数/记录分母、无法评估原因、线索与反证。组合风险保留原组件，不给无解释综合分。中心/研究分析显示分子、分母、随访/暴露与小样本局限，避免惩罚性排名与伪因果疗效结论。

## 9. 快照、风险和三模式

输入总是全量listing。增量比较两个已接受兼容快照，区分新增/修改/消失/不可比。消失先查导出范围，不能自动认定数据删除或风险解决。跨研究、单位/映射/知识/算法版本变动需明确归因，不伪装临床变化。

数据基线与医学决定版本分开。风险保留稳定身份、升级/降级/关闭/重开/合并拆分历史；高风险和严重事件不因新快照未命中自动关闭。规则变化导致不再命中标明“不再适用/无法比较”，不称“已解决”。

日常：本次变化优先＋当前全部中高风险＋需要更新的Query。锁库前：完整风险＋多轮修订影响＋核查包。锁库后：明确固定数据截止与版本，全量研究报告、中心材料、个例入口、风险checklist；修订创建新版本，旧输出不覆盖。

## 10. 看板、医学旅程与输出

研究/中心同构看板：顶部截止日期、覆盖与运行状态；主体研究流向（知情同意→筛选→治疗→研究状态）、风险变化、分母明确的风险分布；下方可筛选受试者表。中高风险不截断前几条，低风险聚合。单击风险在右侧显示依据，显式按钮进入个例，返回保留筛选与滚动。

个例：左侧中心—受试者树；默认全宽fit访视/实际日期轴，允许时间窗放大；AE、MH、CM、IP、检查、住院操作、症状疗效、方案符合性八轨。点/区间与风险用域短名、形状及等级区别，不只靠颜色。部分日期和缺失独立待定，不伪造日期。紧凑编号标记对应详情，不在轨道塞长文。

指标趋势使用真实数值域/日期距离，明确单位/参考区间，缺失不画零；同单位可比较，不同单位先验证换算。多个指标小多图和异常点可查源。不能截顶把不同值画一样，不允许宽屏默认超长横轴只能滚动。

Query工作区：依据—发现—请核实事项，筛选/编辑/保存/导出草稿，版本绑定；不发送。外部报告：上传→原子主张→来源对照/遗漏检查→问题矩阵→带批注副本→按需清洁草稿；页/表/图/脚注覆盖不足不声称全文已审。所有数量、图点、风险、Query和报告能到源记录与条款。

用户页面不显示job/provider/hash/候选信号/正式事实/服务端范围。未知显示“尚未完成/暂无法判断”，不能补为0或已定位。技术诊断进入次级详情。

## 11. 验证与完成标准

新版本首先以正确MG单项目形成资料→数据→AE/MH分析→反证→风险→旅程→来源→Query纵切；其余四项目作为泛化挑战并逐步接入，不再把五项目字段全部完成作为第一条临床价值的前置串行门。五项目全量与至少一个真实兼容增量仍是最终交付要求，未删减。

每改动用少量决定性行为测试、当前源回读、必要ego(lite)宽屏真实交互，阶段结束复盘。恢复丢失的关键迁移行为测试，不重建旧oracle巨矩阵。独立前端review已取得；下游原生review容量失败未完成，不作虚假独立验收。

验收分工程、真实模型、临床来源核对、浏览器、用户使用五层，分别记录；最终用户确认不可由开发者代签。按用户2026-09-06最新指令恢复全局AGENTS执行/会商机制；旧禁用指令已失效。开发执行/审阅节点与产品内置医学harness相互独立。阶段内连续实施，重大路线/权限变化才询问。

## 12. 保留、删除与暂缓

保留来源定位、稳定身份、可恢复graph、风险生命周期、三模式、既有风险评估器与使用中的共享组件。删除候选仅限经引用证明无消费者的旧前端/重复控制器、截图专用CSS、源码字符串钉死测试；先替代再删，Git可恢复。旧运行库和session不清理。

暂缓黑箱综合评分、多agent自由群聊、完整框架重写、五项目同时跑、给每个字段附全份文档反复调用、未验证就引入新数据库/大型依赖。需要新依赖时另做许可与真实集成验证。

## 13. 医学依据与限制

ICH E6(R3)正式版支持以关键质量因素、参与者保护和结果可靠性为重点的相称监查；本设计据此优先关键风险、覆盖与来源，而非过程文书。来源：https://database.ich.org/sites/default/files/ICH_E6(R3)_Step4_FinalGuideline_2025_0106.pdf 。

NCI CTCAE页面提供多个版本并区分事件记录/等级与因果性；本设计据此冻结项目版本并分离判断维度，不直接移植肿瘤试验的报告要求到所有适应症。来源：https://dctd.cancer.gov/research/ctep-trials/for-sites/adverse-events 。

以上是通用设计依据，不替代研究方案、医学监查计划及有权医学人员判断。
