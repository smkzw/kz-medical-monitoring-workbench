## 三、发现清单

### F1【critical / product_bug】研究文件核对 eCRF 门槛死锁，全链路无法推进
- 页面：医学监查 → 数据接入向导 第3步「研究文件与字段映射确认」
- 证据（均为本轮浏览器所见原文）：
  1. eCRF pdf（11MB，226 个图像对象 vs 43 个字体对象，确属截图为主的指南）两次上传后失败：「研究文件自动核对未完成（诊断：document_authority_candidate_not_promotable）。所选文件内容无法完整读取（如扫描版PDF），不能作为权威研究文件」；第二次单独重传为「研究文件未通过完整性核对：未能从这组文件中读取到可核对的内容（如全部为扫描版或文件损坏）」。
  2. 唯一一次出现「哪份是电子病例报告表？…本次未提供电子病例报告表」单选，选中并「保存选择并继续」后流程进入方案 docx 的内容差异确认；确认完成后回到角色列表，eCRF 显示「尚未添加」，下一步按钮显示「请先添加所需文件」且禁用——标记缺失未生效。
  3. DataListing.xlsx 作为研究文件上传 → 触发归属人工确认（已确认，写入裁决档案）→ 复核后失败：「研究文件自动核对未完成（见诊断信息）；可对文件角色作出裁决后重试，或重新上传文件」——整个界面（含来源台账）找不到任何「诊断信息」展示，也没有「对文件角色作出裁决」的入口。
  4. 重试3次（间隔约50分钟）结果完全一致，且第3次显示缓存的旧结论：「最近一次研究文件核对结论：系统还无法确认资料归属…（记录于 2026-10-06T00:01:30）」——归属其实已在更早时刻人工确认过，缓存与事实不符。
- 复现步骤：新建项目（启用医学监查）→ 上传 RUX-03-002_DataListing.xlsx 完成数据接入第1/2步 → 第3步上传临床研究方案 docx → 角色确认时选「本次未提供电子病例报告表」→ 保存并确认 docx 差异 → 观察 eCRF 角色回退为「尚未添加」、下一步禁用 → 再分别试传 eCRF pdf / DataListing.xlsx，观察上述两类失败。

### 本轮验证为「好行为」的点（不算发现，供验收参考）
- 重复上传同一组文件：内容级去重生效，「这组文件与此前上传的内容完全一致，系统会直接复用已有的核对结论；如需重新核对，请更换文件版本后上传」——预防与提示清晰。
- 空表单建项：必填校验完整（试验药物/适应症/研究分期逐项提示+顶部汇总条）。
- 研究编号差异核对：给出「依据位置：filename」并要求医学经理逐项确认，确认写入台账（R1 system_validator 2026/10/6 01:35:37 → R2 local-user… 01:37:28，含确认理由原文）。
- 资料归属人工确认：明确区分「缺少可比对基准」与「文件缺少内容」（「当前项目可能尚未登记方案编号，因此系统缺少可比对的基准，并不代表文件缺少内容」），确认将写入 identity_overrides 裁决档案（含操作者、时间、理由与系统原判定）。
- 方案监查准备对话框如实声明阻断链与「匹配/可使用」语义边界（仅代表文件内容核验通过，不代表监查可读）。

## 四、界面评价（必测项）

**易用性**：向导三步结构与大白话引导（「管理代号请填在这里，不要填入试验药物」「添加文件后，系统会自动识别，不需要您填写技术信息」）对 CRA 友好，建项到数据导入基本不需要培训。但研究文件核对每轮 10–20 分钟只有轮换的状态文案（「独立核对→最后一次核对→复核最后几个分歧」），无进度条、无预计用时；等待期间横幅一直喊「还缺文件」（F4），对低耐心用户是反复刺激。重新打开向导时先显示空白的第1步约半分钟才恢复进度，差点诱导我重复上传。「跳过表结构，直达主操作」实际只是页内滚动到下一步按钮，名不副实。

**逻辑性**：门槛链条本身设计清晰且诚实（建项→数据接入→文件核对→字段映射→运行，每道门在 UI 上都有前置链说明，阻断时的解释完整、不用假数据填充空态——这是同类工具里少见的优点）。但状态机有硬伤：标记缺失不持久（F1-2）、失败结论被缓存且「本次未进入自动核对」后没有清缓存出口、「或/与」口径矛盾（F4）、错误提示引用不存在的操作与信息（F2）。

**美观性**：整体是克制的临床风格，卡片分区、留白、层级清楚；角色 chips（已识别/尚未添加/可稍后添加）一目了然。瑕疵：两处提示文案以「�」截断（F8）、错误以原始 JSON 整包弹出（F3）与整体视觉完成度不匹配；「最后更新」冻结不动削弱了页面"活着"的感觉。

## 六、一句话判断

**这套系统目前不能由一名真实用户独立跑通**：数据接入前两步体验尚可、审计与诚实性设计是亮点，但研究文件核对这道门在"eCRF 是扫描版指南"这一真实世界常见情形下无路可走，且系统给出的三条出路（换可读版本/标记缺失/角色裁决）要么用户做不到、要么界面根本没提供。
