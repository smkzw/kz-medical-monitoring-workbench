## 五、复盘与策略

### 根因归类

1. **字段映射确认是当前唯一的战略锁（R3-01）**：四轮看下来，门禁链是「文档身份→文档完整性→差异裁决→角色裁决→字段识别→字段确认」，前三道本轮已被正面走穿，最后两步合成一处死锁——前端状态机缺采纳分支＋按钮禁用逻辑写反＋后台收尾不收敛，三种面孔（B/C/D）同一根。它不打开，监查引擎永远零运行，植入对照永远「未开考」。
2. **「项目」作为实体零治理（R3-02/04/06/08/10/12/13）**：唯一性、命名规则、模块生命周期、删除归档、创建反馈——整层缺失。测试循环自己就是受害者：B 的垃圾项目只能靠复盘官动 API 收场，真实用户连这个出口都没有。
3. **比对基准用错了对象（R3-09）**：拿系统自己随机生成的临时流水号去和申办方真实协议号比对，任何正规方案 100% 触发拦截。这是 R1-01「身份核对」家族三轮以来第一次被点到真正的病根——此前每轮都在修「拒收后的出口」，没修「为什么拒收」。
4. **长任务行为不可预期（R3-05/07、R2-05/10 族）**：同一文件重传全量重核 52 分钟 vs 被拒文件缓存秒回；页内刷新按钮无效要靠整页刷新；59 表 4 小时无进度透传。用户对系统行为的预期模型建立不起来。
