## 发现清单

### C-01 研究文件完整性核对与晋级判定双重阻断，导致全链彻底中断
- 【页面】医学监查 → 数据接入向导 → 第 3 步「研究文件与字段映射确认」
- 【问题】使用本轮专属真实研究材料（`RUX-03-002_临床研究方案_V1.3.docx` 与 `RUX-03-002_eCRF填写指南_V1.0.pdf`）在第 3 步提交时，系统出现多重校验阻断：
  1. 同时上传 docx 方案与 pdf 指南时，触发 `document_authority_candidate_not_promotable` 诊断，认定内容无法完整读取（如扫描版PDF），拒绝晋级为权威文件；
  2. 单独上传 docx 方案并按向导引导人工确认 eCRF 为「本次未提供」后，系统在字段识别阶段再次报红：`研究文件未通过完整性核对：未能从这组文件中读取到可核对的内容（如全部为扫描版或文件损坏）`，导致字段识别结果输出始终为 0 项，无法生成字段映射。
- 【严重度】**critical**
- 【类别】**product_bug**
- 【证据（看到的现象）】
  - 界面显示：`查看全部字段的识别结果（0 项，按数据域归并列出）`。
  - 警告提示：`研究文件未通过完整性核对：未能从这组文件中读取到可核对的内容（如全部为扫描版或文件损坏）。请更换为可读取的文件版本后重新上传。请稍后重试；若持续失败，请确认字段识别已生成完成。`
  - 底部操作按钮退化为 `重新加载识别结果`（可点击但反复返回上述报错）与 `返回上一步`，主流程无任何正向推进入口。
- 【复现步骤】
  1. 浏览器打开 `http://localhost:5178/`，新建项目 `MX循R22C-RUX`（启用医学监查）。
  2. 第 1 步输入 RUX 本地材料路径并完成 54 表导入。
  3. 第 2 步点击「下一步：让系统核对字段」。
  4. 第 3 步上传 `RUX-03-002_临床研究方案_V1.3.docx`；待识别完成后在文件角色确认单选框中勾选「本次未提供电子病例报告表」，点击「保存选择并继续」。
  5. 观察系统识别结果，界面报完整性核对失败且字段计数为 0。

### C-03 角色裁决引导与后续完整性校验存在逻辑自相矛盾
- 【页面】医学监查 → 数据接入向导 → 第 3 步「研究文件与字段映射确认」
- 【问题】系统给出的业务引导与随后的底层校验规则冲突。
- 【严重度】**medium**
- 【类别】**product_bug**
- 【证据（看到的现象）】
  - 当只有方案 docx 时，系统向导弹窗主动提示用户：`系统只剩以下文件关系无法确定：哪份是电子病例报告表？选择后系统将按电子病例报告表的口径解析该文件的全部内容……标记缺失表示本研究无此类文件。 [o] 本次未提供电子病例报告表 [保存选择并继续]`。

  1. 第 3 步仅传方案 docx。
  2. 依引导勾选「本次未提供电子病例报告表」并保存。
  3. 观察系统后续报错。

## 界面评价

### 易用性 (Usability)
系统在数据接入的前半段表现出了非常成熟的产品易用性：第 1 步同时支持拖拽选择目录、单文件选择以及手动输入本机绝对路径，极大方便了本地受限环境的操作；对于 18 万行、54 张表的超大工作簿，提供了清晰的实时秒数计时和「后台整理可离开页面」的心理预期管理；第 2 步的导入概况能够自动将同目录下的非数据文件准确剔除，并给出明确提示。然而，易用性在第 3 步出现断崖式下跌：当文件校验或解析报错时，界面直接移除了文件选择控件，用户即使拥有新版文件也无法就地替换，且错误提示中的「请稍后重试」让用户陷入无限等待点击「重新加载」的徒劳循环，缺乏清晰的失败退路。

### 逻辑性 (Logical Consistency)
在合规与安全边界上，系统的门禁逻辑体现了极其严谨的医学监查工程思维：在字段映射完成前，下方的监查工作区与「方案事实与规则发布」严格处于 fail-closed 拦截状态，明确展示「先完成字段映射确认，确认完成前不会启动医学监查」，彻底防止了脏数据或无事实依据的下游误判。但是，向导内部的交互逻辑存在闭环缺陷：系统在检测到缺少 eCRF 时，主动提供单选框允许用户裁决「本次未提供电子病例报告表」，但当用户依从保存后，后续识别模块却仍以「未能读取到可核对内容」强行报错，自相矛盾。此外，刷新后虽然通过服务端会话能够恢复至第 2 步，但首屏异步渲染时的闪烁会让用户误以为项目配置已丢失。

### 美观性 (Aesthetics)
整体设计语言严谨、专业。色彩方案采用了医疗软件标准的浅灰底色、高对比度的深蓝字阶与稳重的警示橙色；向导卡片采用清晰的圆角边框与轻微投影，第 1 步到第 3 步的步骤指示器视觉节奏分明。排版在 1440px 与 1920px 下极具质感，但在 1280px 下项目下拉框与顶栏发生文字挤压截断；同时在数据加载期间缺乏骨架屏（Skeleton），直接展示「读取中…」和瞬时错位卡片，削弱了系统的工业级精致感。
