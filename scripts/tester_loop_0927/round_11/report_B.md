## 三、发现清单

### F1【critical / product_bug】研究文件核对对全部6种组合失败，全链路死锁
- 【页面】医学监查 → 数据接入向导 第3步「处理少量疑点」
- 【问题】穷尽三种材料的所有非空组合（docx+pdf、docx、pdf、xlsx+docx+pdf、docx+xlsx、xlsx），「研究文件自动核对」无一成功；底部CTA恒为禁用态「请先添加所需文件」，链路无法推进到字段映射。
- 【证据】各组合核对1.5-3分钟后返回：「研究文件自动核对未完成（见诊断信息）；可对文件角色作出裁决后重试，或重新上传文件。」（5种组合）或「研究文件未通过完整性核对：未能从这组文件中读取到可核对的内容（如全部为扫描版或文件损坏）」（仅pdf组合）。主页面同步显示「字段核对尚未完成，确认完成前不会启动医学监查」；「方案事实与规则发布」页显示「当前项目医学监查来源状态未确认，读取与执行已阻断」。
- 【复现步骤】新建项目→上传 DataListing.xlsx→「下一步：让系统核对字段」→「一次选择研究文件」上传方案docx+eCRF pdf（或任一组合）→等待2-3分钟→观察失败文案；重试与换组合均同结果。

### F2【high / product_bug】断言文本版 PDF「无可读内容（如全部为扫描版或损坏）」与事实不符
- 【页面】数据接入向导 第3步
- 【问题】仅上传 eCRF PDF 时，系统结论为「未能从这组文件中读取到可核对的内容（如全部为扫描版或文件损坏）」。该 PDF 实际有完整文本层——属对用户材料的错误陈述（语义不诚实）。
- 【证据】本机核验（只读自己分到的材料）：`pdftotext -f 1 -l 5 .../RUX-03-002_eCRF填写指南_V1.0.pdf -` 提取出完整中文文本，首页含「eCRF 填写指南」「方案编号 RUX-03-002」「在中国人群中评价磷酸芦可替尼乳膏治疗特应性皮炎的疗效及安全性的随机、双盲、安慰剂对照Ⅲ期临床研究」「Page 页码：1 / 133」；PDF 内含 /FontDescriptor 与约90个带文本绘制操作的内容流。
- 【复现步骤】第3步仅上传该 PDF → 核对完成后读结论文案。

### F3【medium / ux_issue】报错引用的「诊断信息」与「文件角色裁决」在界面上不存在
- 【页面】数据接入向导 第3步失败态
- 【问题】文案让用户「见诊断信息」「对文件角色作出裁决后重试」，但全页 DOM 无任何诊断信息区块、展开项或裁决控件；可用按钮仅「重新核对研究文件／返回上一步／请先添加所需文件」。用户按提示找不到任何可执行动作。
- 【证据】对页面全量遍历 button/[role=button]/select/radiogroup 及检索「诊断」关键字，除该报错段落外无匹配；`document.querySelectorAll("details")` 为空。
- 【复现步骤】任一组合核对失败后观察第3步全部可交互元素。

### F4【medium / ux_issue】错传不支持格式的文件，系统静默丢弃并报出与真实原因不符的错误
- 【页面】数据接入向导 第1步「选择数据」

- 【证据】操作序列如上；台账流水「未通过 2026-10-02 15:33:14 · RUX-03-002_临床研究方案_V1.3.docx · 原因：admission_source_invalid」证明系统其实识别出了格式无效，却未在向导中如实相告。
- 【复现步骤】第1步选择非表格文件→开始导入→读错误文案→对比来源台账原因。

### F5【medium / ux_issue】刷新页面丢失研究文件上传状态，向导收起，恢复成本高

### F6【medium / product_bug】来源台账宣称「失败路径同样可追溯」，但6次研究文件核对失败零留痕

### F7【low / ux_issue】台账事件时间戳为 UTC，与同屏本地时间差8小时
- 【页面】来源台账
- 【问题】事件流水时间「2026-10-02 15:33:14 / 15:35:57」为 UTC，而页面「最后更新 00:06」为本地时间，同屏两种时区无标注。作为"供QA稽查与监管审计"的时间线，易被误读为下午发生的事件。

- 【页面】新建研究项目对话框

## 四、界面评价

**易用性**：三步向导框架清晰，「第几步+做什么」的引导语平实；数据导入的进度反馈（秒数+预期说明）和大文件提示是同类工具里少见的耐心。但错误恢复链路严重断裂：按报错去找「诊断信息」和「文件角色裁决」根本不存在（F3）；错传格式报「路径不存在」（F4）；刷新一下研究文件全丢、还得重走两步（F5）。对出差途中用笔记本的 CRA 来说，这三个坑每一个都足以让人放弃这个工具回到 Excel。

**逻辑性**：门禁逻辑本身自洽且透明——「字段核对未完成前不会启动监查」「来源状态未确认读取与执行已阻断」的因果链在多个页面重复说明，用户能理解为什么被拦。54表清单、行数、辅助表说明与真实文件一致，数据侧的"所见即所传"可信。不逻辑的地方集中在状态语义：失败结论已出，页面却仍挂「系统仍在独立核对研究文件／当前无需逐项确认」的进行时文案（F8）；同一提示整段重复两遍也是状态机分支裸露的痕迹。

**美观性**：（依据页面快照与视觉分析）浅灰底、白卡片、左侧模块导航+顶栏项目上下文的布局整齐，模块划分与医药行业心智相符；主行动按钮用橙色强调、层级清楚。但两处减分：错误/警示用橙色小字段落呈现，既不醒目也不与普通说明文字区分，critical 级阻断在视觉上和帮助文案一样温和；「数据接入」卡片里再嵌一层同名「数据接入」向导卡，同名嵌套加深了层级感，配合收起/展开按钮容易让人不确定自己在哪一层。
