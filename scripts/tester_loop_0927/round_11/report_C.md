## 2. 总结论

**测试结论：FAIL（彻底阻断于数据接入向导第 3 步：研究文档准备情况）**

**核心卡点总结**：
1. **外部 AI 服务不可达且缺乏离线/重试容错（致命死锁）**：系统在第 3 步交叉核对研究文档时强依赖在线大模型接口（glm-5.3-flash），由于运行环境中的代理服务（`http://127.0.0.1:7897`）返回 HTTP 503 快速失败（`[Proxy Fast-Fail] Proxy unreachable`），后台任务直接抛出 `mapping_document_authority_failed`。
2. **失败状态被指纹缓存持久化，用户无法自愈**：后端以文件哈希对核对结论进行强缓存。文档解析失败后，无论是点击界面上的「重新核对研究文件」，还是重新上传相同的研究文件，系统都因哈希命中而提示“这组文件与此前上传的内容完全一致，系统直接复用已有核对结论”，从而反复输出已失败的快照，无法重新发起解析请求。
3. **UI 承诺的人工裁决通道“有文案无控件”（空头支票）**：页面红框警告明确提示用户：“研究文件自动核对未完成（见诊断信息）；可对文件角色作出裁决后重试，或重新上传文件。”然而：
   - 界面上完全看不到任何技术诊断或错误原因（所谓“见诊断信息”不可见）；
   - 前端代码判断 `files.length === 0` 时不渲染任何文档卡片与下拉选择框，导致用户面对“可对文件角色作出裁决”的提示，在界面上根本找不到任何裁决按钮或下拉列表；
   - 底部主按钮「请先添加所需文件」永久置灰（disabled），形成无解闭环。

## 4. 界面综合评价（数据管理员专业视角）

### ① 易用性（Usability）
- **亮点**：向导式的步进结构非常清晰（第 1 步选数据 -> 第 2 步看概况 -> 第 3 步处理疑点），每一步都有说明文字告知“原始文件保持不变”，这一点对于极其注重数据完整性（Data Integrity）的数据管理员来说非常友好且具备安全感。
- **缺陷**：容错与自愈能力极度脆弱。第 1 步多选了材料文件便报出风马牛不相及的“目录不存在”；第 3 步遇到外部服务波动时，既不给用户明确的技术归因，又不提供手动降级通道（例如允许数据管理员手动指定哪个是方案、哪个是 CRF），而是直接把主流程完全封死，让非开发人员彻底束手无策。

### ② 逻辑性（Logic & Consistency）
- **亮点**：第 2 步的表结构画像逻辑非常严谨，将 59 张表、3557 行数据按 DOMAIN 逐一罗列，支持折叠展开，并准确解析出各表的列名与数据类型（如 `AE--不良事件` 的 SITENM 文本、SITEID 数值等），数据搬运无丢失，字段识别精准。
- **缺陷**：状态流转存在严重断层与自相矛盾。第 3 步在文档核对失败时，文案提示“可对文件角色作出裁决”，但界面的业务逻辑却因为解析失败没有返回文件对象而直接隐藏了裁决入口，出现了“提示语诱导用户裁决，界面却无控件可操作”的严重逻辑脱节；同时，指纹缓存机制在失败场景下未做“清除缓存重新请求”的容错设计，导致相同哈希文件永久复用失败态。

### ③ 美观性（Aesthetics & Layout）
- **亮点**：界面整体配色规范，延续了康哲工作台沉稳专业的克制风格。表头、卡片、步进条对齐严整，字体与字阶层次清晰。第 2 步 59 张数据表的抽屉式微缩预览设计得体，信息密度适中，视觉负荷控制较好。
- **缺陷**：错误反馈界面的视觉组织较为粗糙。告警卡片仅以简单的红底展示单调的通用文案；在异步识别过程中，按钮频繁在“正在核对…”、“请先添加所需文件”之间跳动，且缺乏具体的阶段进度条（如：已上传、文本解析中、实体抽取中），用户在面对漫长等待时容易产生系统卡死的焦虑。

## 5. 等待与卡点时长记录

- **新建项目处理等待时长**：约 **40 秒**（弹窗一直处于“创建中”，未自动退出，后经手动刷新页面确认已创建完毕）。

- **第三步研究文档上传与交叉核对调用时长**：
  - 首次上传双 docx 识别：约 **15 秒** 后返回 HTTP 409 失败。
  - 上传单方案 docx 尝试破缓存识别：约 **15 秒** 后返回 HTTP 409 失败。
  - 重新选择双 docx 文件上传：约 **4 秒** 后直接命中持久化失败缓存并弹窗。
- **卡死停滞与观察时长**：因代理服务故障导致文件核对陷入死锁，且界面无法人工放行，前前后后在向导第 3 步刷新、重试、观察等待累计超过 **35 分钟**，确认系统已进入确定性死循环，符合等待纪律终止条件。

## 6. 一句话总结论

**“这套系统目前无法由一名真实数据管理员（DM）独立跑通——尽管表结构画像与数据识别功能专业扎实，但系统在关键的研究文档交叉核对环节强耦合外部 AI 服务，一旦代理或网络发生 503 异常便将失败死死锁定在文件指纹中，加之界面裁决控件在解析失败时彻底隐形，真实用户必在数据接入向导第 3 步遭遇完全不可逆的流程中断。”**
