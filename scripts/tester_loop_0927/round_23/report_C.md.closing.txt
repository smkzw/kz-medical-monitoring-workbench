### 二、核心发现清单

1. **F1【critical / product_bug】超大规模表映射候选生成吞吐极低且同步霸占写锁，导致整站假死与业务流程死锁**
   - **页面**：医学监查 → 数据接入向导 第 3 步「研究文件与字段映射确认」
   - **证据**：后台处理 59 表中大型 Listing 时串行持有 `acquire_product_write_gate` 锁，导致前台 HTTP 接口级联超时（5178 端口白屏挂起近 9 分钟）；字段识别耗时失控（4 小时以上仅完成 53/59 表共 1455 字段），主按钮持续置灰，业务全链彻底阻断。
2. **F2【high / ux_issue】模拟离开 1 小时情境下前端向导状态未完全持久化，重新进入时向导步骤倒退**
   - **页面**：医学监查 → 数据接入向导
   - **证据**：离开 1 小时返回后刷新页面，向导组件默认退回到第 1 步并显示「选择本机数据文件夹」，卡片显示「开始数据接入」而非继续进度，极易误导临床用户重复操作或重新上传。
3. **F3【medium / product_bug】第 1 步文件上传未做前端类型拦截，混入 docx 时报错文案答非所问**
   - **页面**：数据接入向导 第 1 步「选择数据」
   - **证据**：单文件选择器选入 docx 时前台照常接收显示「共 3 个文件」，提交后报 422 `admission_source_invalid`，但前台 Alert 报错文案误报为「未找到该数据位置：目录不存在或路径不可访问」，将格式不支持错判为目录路径问题。
4. **F4【medium / medical_accuracy】PV 专员视角：严重度未知（Unknown/Missing Severity）与未编码术语的识别口径在映射前置层缺乏显式规则约束**
   - **页面**：医学监查 → 数据接入向导 第 3 步「字段映射」
   - **证据**：AE 包含 73 列多重严重度与因果字段（`AETOXGR`, `AESEV`, `AESER`, `AEREL`），向导仅做常规列名匹配，未在字段映射前置层显式澄清“严重度未知”是否会被后续规则引擎静默填充，存在医学语义合规隐患。
5. **F5【low / cosmetic】向导进行中主按钮文案频繁跳变，缺乏确定性百分比或剩余表数进度指示**
   - **页面**：数据接入向导 第 3 步底部操作栏
   - **证据**：主按钮在「正在读取系统识别结果…」与「正在生成字段识别结果…（自动刷新进度，无需手动刷新）」之间每隔数秒闪烁切换，未提供已完成表数百分比与 ETA。

### 三、三维界面评价摘要

- **易用性（Usability）**：线性三步向导降低了技术门槛，建项时区分药物与管理代号设计贴心，且明确承诺“原始文件保持不变”；但面对长时任务缺乏进度透明度与耗时预期，主按钮长时间置灰降低了掌控感。
- **逻辑性（Logical Flow）**：前置门禁（Fail-Closed）表现扎实，未确认映射时「方案事实与规则发布」严格阻断并给出清晰原因；但后台任务与前台 HTTP 线程锁耦合严重，文件格式校验与路径错误归因存在断层。
- **美观性（Aesthetics & Visual Quality）**：采用规范低饱和度现代临床工程设计风格（深色顶栏 + #F6F7F9 浅灰底），中文域代码字典映射专业规范；但错误提示与进行中状态的文字跳变略显生硬。
