## 3. 核心发现汇总

1. **【发现 1】研究文件上传后交叉核对陷入死锁，超 45 分钟无响应（Critical / `product_bug`）**
   - **现象**：上传 `MY008-302_研究方案_V1.1.docx`（443KB）与 `MY008-302_DraftCRF_V0.1.docx`（623KB）后，前端持续高频向 `study-documents/resolve` 与 `ai/queue` 轮询达 46 分 11 秒，状态文本固定显示 `系统正在核对已上传的研究文件，请稍候……系统正在识别并交叉核对…`，主操作按钮置灰不可点击，全链中断。
2. **【发现 2】向导处理期间刷新页面，向导收起且延迟闪现第 1 步未选文件假象（High / `ux_issue`）**
   - **现象**：长任务等待期间刷新页面，向导默认闭合；重新点击「开始数据接入」展开后，首屏展示第 1 步空表单（`未选择任何文件`），延迟 3~5 秒后才跳回已完成的第 2 步，严重误导用户认为数据已丢失。
3. **【发现 3】页面首屏加载时顶栏元数据出现两级重绘与视觉跳跃（Medium / `cosmetic`）**
   - **现象**：页面 reload 时，顶栏经历“正在加载项目”→“适应症：读取中… / 当前来源：未配置当前模块”→“阵发性睡眠性血红蛋白尿症 / 医学监查”，工作区卡片在短时间内频繁重排，缺乏骨架屏平滑过渡。
4. **【发现 4】第 2 步查看导入概况中，59 张表结构全量平铺，信息过密且缺乏检索折叠（Low / `ux_issue`）**
   - **现象**：展开 59 张表结构后单页渲染超过 6000 行 DOM 文本，无表名搜索框亦无单表手风琴折叠，宽屏下查阅核心表字段体验较差。

## 4. 界面专业评价（数据管理员视角）

- **易用性**：新首页子系统卡片分流与建项表单体验流畅。但从第 2 步跨入第 3 步后缺乏进度与阶段反馈（无百分比、无当前阶段），呈现“黑盒式”无限转圈，严重影响操作确定性。
- **逻辑性**：第 2 步已完成 59 张表结构与列元数据提取，但第 3 步强行将“字段映射确认”硬绑定在“方案/eCRF 全文交叉核对结论”之后，一旦文档语义解析任务阻塞，下游字段核对即全盘被阻断，缺乏降级与容错解耦。
- **美观性（敢不敢给领导演示）**：整体色彩与标签质感专业稳重；但**不敢直接给领导演示**——主要由于文档核对长期卡死且无进度条、59 张表展开后缺乏卡片分栏出现瀑布流失控、以及刷新时顶栏状态多次抽搐跳动。
