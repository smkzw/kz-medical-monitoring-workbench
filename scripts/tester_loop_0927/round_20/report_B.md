## 发现清单

### B-1【新建研究项目对话框】创建已成功但对话框永久停留「创建中」，退出控件全部禁用，用户被锁死
- 严重度：high
- 类别：product_bug
- 证据：提交后项目下拉中已出现「MX循R20B-MY008 · MY008211A · 阵发性睡眠性血红蛋白尿症（PNH）· III期」（创建实际成功），但对话框按钮停在「创建中」≥50 秒不关闭；随后出现提示「创建请求仍在处理中…您可以继续等待，或关闭本对话框后刷新页面查看项目是否已创建」。实测该状态下三个退出控件全部 disabled：`[{关闭新建项目对话框,disabled:true},{取消,disabled:true},{创建中,disabled:true}]`；在对话框内按 Escape 也不关闭。刷新页面又遭遇 `page.reload`/`page.goto` 等待 load 超时，标签页一度落到 chrome://new-tab-page，再次手动进入 URL 才恢复。
- 复现步骤：新建项目 → 填写必填项（试验药物/适应症/研究分期）→ 勾选启用医学监查 → 创建 → 等待约 15 秒观察按钮与提示 → 尝试 × / 取消 / Escape / 刷新。
- 附注：提示文案让用户「关闭本对话框」，而关闭控件本身不可用，属于误导性指引。

### B-2【新建研究项目对话框】模态焦点管理缺陷：焦点逃逸到背景页、×不在Tab序、创建中状态下取消/创建脱离Tab序、Escape全程无效
- 严重度：high
- 类别：ux_issue（本轮键盘专项核心发现）
- 证据（均为实测 Tab/Shift+Tab 轨迹）：
  1. 模态打开时焦点正确落入第一个输入框（好），Tab 序 项目名称→试验药物→适应症→研究分期→监查checkbox→取消→创建项目 逻辑正常（好）；
  2. 但 Shift+Tab 回走时焦点逃逸出对话框，实测焦点落在背景页按钮「低—开放风险」（模态无焦点圈禁）；
  3. 「创建中」状态下从 checkbox 按 Tab 直接跳出对话框到背景导航（取消/创建按钮从 Tab 序消失，因其 disabled），实测轨迹「…INPUT(checkbox) → 项目总看板…导航 → 返回项目总看板」；
  4. 「关闭新建项目对话框」(×) 按钮在多轮 Tab 走焦中从未出现（12 连 Tab 未达）；
  5. Escape 在框外焦点与框内输入框焦点下均不能关闭对话框（各实测一次）。
- 复现步骤：打开新建项目对话框 → 任意提交一次使其进入「创建中」→ 分别尝试 Tab/Shift+Tab 走焦与 Escape。

### B-3【新建研究项目对话框】键盘输入期间字段值被静默篡改/丢失（数据完整性风险）
- 严重度：high
- 类别：product_bug
- 证据（按现象记录，机制不臆断）：

### B-9【键盘专项·补充】原生 select 控件在合成键盘事件下不可操作；向导第1步的两种选择方式疑似非按钮
- 严重度：medium（产品侧与环境侧各半，纯浏览器内无法判定归属）
- 类别：ux_issue
- 证据：
  1. 研究分期 select：焦点确认在 select 上，连按 5 次 ArrowDown、typeahead「III期」、Enter、Tab 失焦后值均不变或变为非法值「期」；项目下拉 select 同样 ArrowDown/typeahead 无效。最终两次改用编程选择（selectOption）——这是主流程中仅有的两处非键盘操作，如实报告。可能是本自动化环境合成按键事件的限制（真人物理键盘未验证），但「值一度变为选项表中不存在的『期』」是页面自身状态异常，与注入方式无关；
  2. 向导第1步「选择数据文件夹 / 选择单个数据文件」在可及性快照中是纯文本节点（无按钮角色、无操作 ref），页面内也无 input[type=file] 元素（两次枚举 input 均为空），键盘用户疑似只能走「手动填写数据位置」文本框——因自动接入未走选择路径，未最终验证不可达性；

## 键盘专项小结（焦点丢失与不可达控件汇总）

- 焦点丢失/逃逸：模态对话框 Shift+Tab 逃逸到背景「低—开放风险」按钮；「创建中」状态 Tab 从 checkbox 直接逃出对话框到背景导航（B-2）。
- 不可达控件：对话框 × 关闭按钮（从未进入 Tab 序）；「创建中」状态的 取消/创建（disabled 退出 Tab 序）；向导第1步两种文件选择方式（疑似非焦点元素，未终验）；Escape 对该模态全程无效。
- 可正常键盘操作：对话框内表单链（输入/Tab/Space 勾选/Enter 提交）、顶栏模块导航、医学监查页全部按钮（开始数据接入/查看59张表/下一步/返回上一步）均可用键盘走通。
- 测试侧偏差（如实）：两处 select 用 selectOption 编程选择；刷新用浏览器级 reload/goto（Cmd+R 合成键无效）；走焦前用 focus() 播种起点（纯 Tab 起点走查另做过，如从 body 连续 12 个 Tab 到「新建项目」）。

## 界面评价

**易用性**：必填缺失的拒绝方式是清楚而非静默的——空表单提交即得「请填写试验药物/请填写适应症/请填写研究分期」三条逐项错误，对话框不关；服务故障时给出超时阈值（20 秒）、重试按钮与检查建议，重试即恢复。但流程级易用性被两处死锁拖垮：创建对话框「创建中」锁死（B-1）与字段识别无限循环（B-6），后者连「卡在哪一步」的信息都没有，用户只能干等或反复刷新。向导刷新后重置回第 1 步、又不允许真正重新选择数据，恢复路径自相矛盾。

**逻辑性**：链路门槛设计是通的——未确认映射前用显式阻断门拦住医学监查启动（文案明确），docx 在导入步被忽略并说明改在第 3 步处理，第 2 步对「59 张表含辅助表、不预先剔除」的口径交代清楚，这些都是好逻辑。反面：向导声称「选择本机数据文件」却允许零选择直接导入（B-4）；「无需手动刷新」与「请稍后刷新进度」两处文案互相打架（B-6）；提示用户「关闭本对话框」而关闭按钮被禁用（B-1）；台账与管道内数据不同步（B-5）；录入「（初治PNH）」入库变「（PNH）」未经确认（B-3.4）。

**美观性**：样式抽取+视觉模型分析显示——Inter/Noto Sans SC 字体栈，白底浅灰分区，当前模块用橙色高亮（底 #FFF4ED / 字 #D95710）标识位置，标题层级 28px/700 与正文 14px 拉差清晰，4px 小圆角、按钮内边距紧凑统一；左导航+顶栏+内容三区栅格对齐整齐，截图分析未见错位或破版。密度偏高（顶栏塞入项目元数据+4 个计数徽章+通知），全部计数为 0 时仍占满一行，视觉噪音偏大；风险摘要的「紧急/高/中/低」未见颜色或形状分级编码，仅文本并列，弱化了监查系统最该有的风险视觉语义。整体属于克制的工具型设计，无装饰性冗余。

## 一句话判断

**这套系统目前不能由一名真实用户独立跑通**：用户会先在建项对话框的「创建中」锁死处被迫刷新自救，随后必然停在字段识别的无限循环上，且界面给不出任何卡点信息。
