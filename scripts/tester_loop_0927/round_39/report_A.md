## 发现清单

### R39-A-01：子系统选择对话框打开后，焦点仍留在背景页面

- 【页面】项目总看板 → 新建研究项目：选择子系统。
- 【问题】打开对话框没有将键盘焦点移入对话框；后续 Tab 先经过两个背景控件，才到达对话框关闭按钮。增加无意义按键，并使用户难以确认当前操作区域。
- 【严重度】medium。
- 【类别】ux_issue。
- 【证据（看到的现象）】用首页顶部「新建项目」的 Enter 打开对话框后，当前焦点仍是文本为「新建项目」的 BUTTON。随后实际顺序是：背景无文字 BUTTON → 背景「新建项目」BUTTON →「关闭新建项目对话框」→ 医学写作卡 → 医学监查卡 → 入排审核卡 → 取消 → 前往医学监查配置。没有激活背景控件；记录的是对话框刚打开时的焦点进入问题，不声称已经验证所有边界的焦点陷阱。
- 【复现步骤】从未选择项目的首页用 Tab 到顶部「新建项目」；Enter；观察当前焦点；连续 Tab，记录到达对话框关闭按钮前经过的背景控件。

### R39-A-02：研究分期可聚焦，但本轮键盘输入无法完成选择（待归因）

- 【页面】「在医学监查配置新研究项目」面板。
- 【问题】研究分期是必填项。Tab 可到达下拉框，截图有蓝色焦点边框，但多种键盘选择方式都未改变「请选择」，无法完成仅键盘建项。
- 【严重度】high（本轮键盘任务的阻断影响；**不是已确诊产品 high 缺陷**）。
- 【类别】ux_issue（页面与工具责任待归因）。
- 【证据（看到的现象）】Tab 后页面焦点为 SELECT，值仍为空。尝试 ArrowDown 连续六次、Space 后方向键/Enter、End、Alt+ArrowDown、文字首字符选择，均未成功。键盘激活「创建项目」后显示「请填写研究分期」和「请先补全标记为必填的项目信息」，仍停在面板。对已经通过 Tab 到达的同一控件，补充使用 ego-browser 的定向键盘 press、原生键盘事件及页面前台激活，仍无改变；没有更换入口或浏览器空间。
- 【输入工具疑点】当页面报告焦点为 SELECT 时，`keyboard.type("分")` 反而将前一个「适应症」输入框改成「分」。已用键盘恢复「银屑病」。这使得“必然是产品禁止键盘选择”的结论不成立。该输入异常已通过工具问题反馈渠道记录，未改动应用文件。
- 【复现步骤】只选医学监查 → 前往医学监查配置 → 填写前三项 → Tab 到研究分期 → 尝试方向键/Space/Enter → 观察下拉值 → 键盘激活创建项目，观察必填校验。
- 【归因边界】本轮只能确认所用浏览器环境下的键盘链阻断；需要同入口真实物理键盘复核，才能把该项归入已确诊产品缺陷。没有用鼠标或程序选值补跑，再把它描述为键盘通过。

### 美观性
