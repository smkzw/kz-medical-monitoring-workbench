## 三、发现清单

1. 【数据接入向导·第1步】【选择数据文件夹后「开始导入」必然失败，且「重试」无效】【critical】【product_bug】
   - 证据：webkitdirectory 文件选择成功，界面显示「已选择"synth_pso"，共 3 个文件」；点「开始导入」报「未找到该数据位置：目录不存在或路径不可访问。请核对路径后重试」；此时「数据位置」手动框为空（DOM 验证）；点「重试」重复同样错误（≈10:24）。改在「数据位置」填目录绝对路径后导入立即成功（≈10:26），证明数据本身无问题。
   - 复现：新建监查项目 → 数据接入 → 「选择数据文件夹」选任意真实数据目录 → 「开始导入」→ 报数据位置不可访问 → 「重试」→ 同错。

2. 【数据接入向导·第3步】【字段对应关系确认/复核阶段永不完成，链路中断】【critical】【product_bug】
   - 证据：11:57 答复唯一医学疑点后进入「正在确认字段对应关系…→系统正在复核少量疑点，尽量减少需要您判断的内容…」；主按钮（确认）一直 disabled（DOM 验证）。四轮静默等待 29/18/32/13+ 分钟无完成；13:18 一轮明确报「系统复核暂未完成，请稍后重试。原始数据不会受到影响。」；点「重新加载识别结果」后又回到「正在确认→复核」。期间刷新/重进 5 次，每次都重走「确认→复核」循环（13:35 最后一轮仍在「正在确认字段对应关系…」）。步骤累计 99 分钟（11:57–13:36）无净进展。
   - 复现：完成发现1的导入并上传 docx、确认归属与角色、答复医学疑点后，停留在第 3 步等待，观察「复核」状态 ≥45 分钟。

3. 【数据接入向导·第3步】【「暂停整理」按钮无响应且点击调用挂起】【high】【product_bug】
   - 证据：12:55 点击「暂停整理」，浏览器点击调用 5 分钟未返回（无任何 JS 对话框，page.info() 无 dialog）；并行进程可正常读取页面，页面状态无任何变化（按钮文案仍「暂停整理」，复核状态照旧）。作为对照，其余所有按钮点击均即时返回。
   - 复现：第 3 步复核等待期间点「暂停整理」，观察按钮与页面状态。

4. 【数据接入向导·第3步】【长时间复核无进度反馈、失败文案无归因】【medium】【ux_issue】
   - 证据：「系统正在复核少量疑点，尽量减少需要您判断的内容…」持续 30+ 分钟无进度指示、无预计时长；失败时仅「系统复核暂未完成，请稍后重试。原始数据不会受到影响」，不说明原因（超时/数据问题/服务问题），用户无从判断是否该等待、重试或报障。
   - 复现：见发现2等待过程。

5. 【数据接入向导·第3步】【docx 上传后约 13 秒界面零反馈】【medium】【ux_issue】

   - 复现：第 3 步「一次选择研究文件」提交文件后立即观察界面。

6. 【数据接入向导·第3步·归属确认】【药物/适应症明明一致却不自动匹配，把可自动判定的事推给人工】【medium】【product_bug】

   - 复现：按本流程建项（药物/适应症与文件一致、不登记方案编号）→ 上传方案 docx → 观察归属确认面板出现。

7. 【数据接入向导·第3步·医学疑点】【方案与数据在剂量/给药途径上的矛盾未被系统提出（在已到达范围内）】【medium】【medical_accuracy】

   - 复现：走本流程至字段疑点出现，比对系统疑点清单与上述材料内在矛盾。

## 四、界面评价

- 易用性：三步向导骨架清晰，每步附带口径与边界说明（如「确认前不会生成可用于监查的数据；确认后也只保存字段对应关系」），错误面板给出「重新开始/重试」双出口，第 3 步「研究方案/eCRF 已识别、研究者手册可稍后添加」的角色卡片一目了然。但两条硬伤拉低易用性：首选文件夹导入路径直接失败，用户须自行想到改手填绝对路径（发现1）；复核等待 30+ 分钟无任何进度反馈（发现4），真实用户只能干等或反复刷新。
- 逻辑性：状态机的前置链表述是亮点，「方案事实与规则发布」抽屉把「为什么阻断、还差哪几步、完成前阻断为预期」讲得完整诚实，监查入口「字段核对尚未完成，确认完成前不会启动医学监查」与向导状态互相印证（本轮未观察到状态归一矛盾）。逻辑瑕疵：「医学监查首页」按钮点击无效果（发现8）；「暂停整理」疑似功能失效（发现3）；刷新后向导折叠并重走「识别→核对」，虽然数据不丢，但每次重进都要 1–2 分钟才回到第 3 步，排障成本高。
- 美观性：基于 DOM 文本的评价（本轮 CDP 截图超时，未能成功取得整页截图，色彩/留白无法置评，如实说明）：层级结构合理——步骤条（第一步/第二步/第三步）+ 域卡片（AE--不良事件 9 个字段…按域归并）+ 底部主/次按钮的布局自洽；字段清单「表--域名 · 变量名 + 类型」的排版对实施工程师友好；文案措辞总体专业克制（「口径：」「仅在需要时展开」）。扣分点：复核等待文案长时间占据主按钮位置且无进度条/计数变化，视觉上「活着」的系统显得死了；错误面板文案与数据位置输入框距离较远，首次报错时不易意识到两者关联。
