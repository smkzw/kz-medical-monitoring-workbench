## 三、发现清单

### F1【医学监查·数据接入向导（第三步）】字段识别进度冻结 ≥46 分钟，主流程被阻断
- 严重度：critical；类别：product_bug
- 证据：识别计数按分钟轮询（浏览器保持打开，期间多次以键盘按"刷新识别进度"）：0→16→20→25→52→100→124 后停止变化；此后连续 4 个观察窗（8min+16min+10min+10min，加首窗尾部约 2.5min，合计 ≥46 分钟）读数恒为 `{"fields":"124","generating":true}`，页面文案"已识别 124 个字段，识别仍在生成中，完成后会显示结论…"，主按钮"正在读取系统识别结果…"`disabled=true`。刷新识别进度（键盘 Enter）多次无效。
- 复现步骤：新建项目（启用医学监查模块）→ 数据接入：手动填写数据位置导入 MY008-302_DataListing.xlsx → 上传两个 docx → 逐项确认内容差异 → 等待字段识别 → 观察计数在 124 处停止且按钮永不启用。

### F2【医学监查首页】持久告警"当前内容暂不可用 / 暂时无法安全打开此项目"，重试与整页刷新均不消失
- 严重度：high；类别：product_bug
- 证据：项目创建成功当刻页面即渲染 `role=alert` 文案"当前内容暂不可用——暂时无法安全打开此项目，请保留原项目并联系支持。"（DOM 位于 main.monitoring-page 直下）。键盘点击"重新读取"3 秒/8 秒后复查仍在；整页 reload 后仍在；直至测试结束（≥1.5 小时后）仍在。告警不说明"哪个内容"不可用、对下方仍可操作的数据接入向导是什么关系——同一页面一边报"无法安全打开此项目"、一边允许继续导入并识别了 124 个字段，语义自相矛盾。
- 复现步骤：新建项目并进入医学监查模块 → 观察告警 → 点"重新读取"→ 刷新页面 → 告警始终存在。

### F3【内容核对】研究编号比对基准失真：系统内部流水号 + 项目名碎片被当作"当前项目研究编号"（R3-09 复现，MY008 材料）
- 严重度：high；类别：medical_accuracy
- 证据：两个 docx 的内容核对均显示——"文件中出现的研究编号样字符串 / 当前项目：**MW-III-BCFC3C41 / MW-III-BCFC3C41-DRAFT / R4B-MY008** / 文件内容：未识别到有定位依据的研究编号样字符串"。建项表单只有 项目名称/试验药物/适应症/研究分期 四项，**没有研究编号字段**，材料的真实编号 MY008211A-PNH-3-02 无处可填；MW-III-BCFC3C41 显然是系统内部生成编号，R4B-MY008 是我项目名的碎片。以失真基准去比对，两份真材料必然报警，用户只能逐项点"差异不影响本次监查，继续使用"——核对从把关退化为必点确认（狼来了效应）。界面未提供修正研究编号的入口。符合上一轮已知问题 R3-09（内部流水号作比对基准），本轮以 MY008 两表材料再次复现。
- 复现步骤：同 F1 前三步 → 在"系统发现以下内容差异"面板读取"当前项目"一侧的编号串。

### F4【数据接入向导】表数口径不一致且无解释：导入概况 59 张表 vs 字段识别 22 张表
- 严重度：medium；类别：ux_issue（数据口径标注缺失）
- 证据：第二步导入概况显示"1 个文件 · 59 张数据表 · 3557 行数据"；第三步字段识别区显示"已识别 22 张数据表"。两处均称"数据表"，口径差异（是否剔除空表）界面无任何说明。数据管理员视角：同名指标两个数而无口径注记，属于数据语义不透明。
- 复现步骤：导入 xlsx 后先读第二步文案，再进入第三步读"已识别 N 张数据表"。

### F5【键盘专项记录】焦点丢失与不可达控件（本轮特别情境）
- a) **Tab 循环焦点落入 BODY**（severity low，ux_issue）：项目总看板上 Tab 从最后一个可聚焦控件（空态"新建项目"按钮）继续按，焦点落到 `<body>`（`document.activeElement===body`，多次观察到），再一次 Tab 才回到首个控件（品牌按钮）。正常应在末元素后直接回绕。
- b) **原生 select 键盘改值在本环境不可达**（severity low，ux_issue，环境限制如实标注）："研究分期" select 聚焦后连按 ArrowDown ×9 值不动；Space+方向键×5+Enter 亦不动；挂探针确认 keydown 事件已送达且 `defaultPrevented=false`，说明无页面拦截，疑为无头 Chromium 原生 select picker 无法弹出所致。前缀输入可用但不稳（"III"匹配到"II期"）。**本轮对该控件用 selectOption 程序化兜底 1 次（非鼠标），其余全部键盘操作，如实记录。**不判产品 bug。
- c) **焦点无操作间隔漂移导致误输入**（severity medium，ux_issue）：研究分期 select 上焦点在两次操作间隔后漂移到"适应症"输入框（页面重渲染未保持焦点），我随后输入的"III期"落进适应症框（值变为"…（PNH）期"），且 select 显示值同步变化。真实用户在页面自动刷新时同样会中招。已当场发现并全选重输纠正。
- d) **对话框不自动聚焦首字段**（severity low，ux_issue）："新建研究项目"对话框打开后焦点仍停在触发按钮上，需自行 Tab 进表单。
- e) 正面：「数据位置」手动输入藏在折叠 `<details>` 内，但 summary 可 Tab、Enter 可展开、输入框随后可达——键盘路径完整。
- f) 合理行为（非问题）：未选项目时 8 个模块导航按钮 disabled 不可 Tab，选中项目后恢复可达；disabled 控件不出现在 Tab 序列符合预期。

### F6【新建项目对话框】对话框头部出现模块标签「医学写作」
- 严重度：low；类别：cosmetic
- 证据：对话框结构为 `dialog "新建研究项目"` 内先渲染 text "医学写作" 再渲染 heading "新建研究项目"。从医学监查链路进入却标注"医学写作"，模块归属标签错乱或残留。
- 复现步骤：点击"新建项目"→ 读对话框首行文本。

### F7【数据接入·第一步】文件夹选择输入在 FileChooser 单文件注入后不注册（webkitdirectory）
- 严重度：medium；类别：product_bug（在无文件夹选择器的环境主路径失效）
- 证据：`input#monitoring-admission-files` 带 `webkitdirectory` + `accept=".csv,.xls,.xlsx,.xlsm"`；键盘 Enter 打开 chooser 后 setFiles 单个 xlsx 成功返回，但随后 `input.files.length===0`，界面不识别。只能展开折叠区改用"手动填写数据位置"目录路径（该 fallback 有效）。桌面真实用户用文件夹选择器大概率可用，但主路径脆弱、fallback 可见度低。
- 复现步骤：数据接入第一步 → 用文件级注入（非文件夹）设置该 input → 检查 files.length 与界面文件计数。

### F8【整体等待体验】长后台步骤零进度反馈
- 严重度：medium；类别：ux_issue
- 证据：docx 交叉核对 8 分钟、字段识别 45+ 分钟，全程只有一句静态文案（"系统正在识别并交叉核对…"/"识别仍在生成中，请稍后刷新进度"），无进度条、无当前子步骤名、无预计时长；"刷新识别进度"按钮与自动轮询的关系未说明；"资料整理控制"区有"暂停整理"按钮但无暂停后果/恢复说明。真实用户无从判断"该等"还是"已死"（本轮恰好在 45 分钟后仍无法区分）。
- 复现步骤：进入任一长后台步骤，观察反馈元素种类与更新频率。

## 五、界面评价

**易用性**：主链路的引导式三步向导、每步禁用态按钮与解释文案总体合格；但两处关键通路埋得深——数据文件必须走折叠的"手动填写数据位置"（F7），研究文件上传框出现在确认差异之前一步却无前置提示"此处需要方案/CRF"，我是被"请先添加所需文件"的禁用按钮顶回去才找到上传框。长时间等待无任何进度反馈（F8），45 分钟后用户只能盲等或放弃。键盘可用性总体尚可（按钮/输入/summary/文件框均可达），但焦点保持有缺陷（F5-c），对话框不落焦点（F5-d）。

**逻辑性**：最大的逻辑裂缝是 F2——同一页面"无法安全打开此项目"的告警与"正在识别 124 个字段"的向导并存且互不引用；其次 F4 的 59 表 vs 22 表两个口径无注记；F3 的编号基准失真让内容核对这一关在 MY008 材料上必然报警、必然人工放行，流程存在但已失去区分度。步骤间状态推进（差异确认→已识别→识别中）本身顺畅，文案多为用户语言而非技术语言，这点好。

**美观性**（注：本环境 CDP 截图全程超时，无法做像素级评估，以下基于可访问性树、结构与计算样式）：字体栈 Inter + Noto Sans SC/PingFang 落地中英混排；标题层级克制（主标题 25px/700）；禁用主按钮用浅灰底(238,241,244)+灰字(125,135,146)，禁用态视觉明确；步骤条"第 一 步/选择数据"的中文数字间隔排版有设计感；域·字段列表"AE · AEACN1 文本"的两列结构清晰。告警区白底红字层级可以，但持久不消失（F2）使其从提示变成视觉噪音。
