## 发现清单

### A-01｜缺失 eCRF 的选择未使必要文件门放行
- 【页面】医学监查 → 数据接入 → 第 3 步「处理少量疑点／研究文档准备情况」
- 【问题】用户明确选「本次未提供电子病例报告表」，并完成方案归属和研究编号差异确认后，页面仍将电子病例报告表标为「尚未添加」，禁用「请先添加所需文件」。方案已显示「已识别」。
- 【严重度】high
- 【类别】product_bug
- 【证据（你看到的现象）】22:12 左右保存缺失选择，22:14 方案显示「已识别」，22:17 刷新并重进向导仍显示 eCRF「尚未添加」且下一步按钮 `disabled=true`。所给材料为 **eCRF 填写指南**，不是电子病例报告表；不能把指南指定成不存在的表来绕过门。
- 【复现步骤】新建启用医学监查的项目 → 上传该 Data Listing → 第 3 步单独上传并核对方案 → 在文件角色疑点选择「本次未提供电子病例报告表」并保存 → 确认方案管理代号差异 → 查看研究文档准备情况和下一步按钮；刷新后重进同一步仍可见阻断。

## 界面评价

- **易用性：** 文件选择、54 表／180793 行概况和「辅助表也计入」说明能帮助核对导入对象；但选定单个 Data Listing 后状态只显示「所选文件」而不是文件名，研究文件重试和刷新后也难确认当前保存的是哪次提交。阻断态只给「请先添加所需文件」，没有指向已选「未提供」为何无效。
- **逻辑性：** 不把 eCRF 填写指南自动当作 eCRF、不在文件归属不确定时直接发布权威事实，符合证据链的审慎要求。反面是已经识别方案、已经选定 eCRF 未提供后仍要求「方案或 eCRF」，与界面给出的二选一口径相矛盾，流程不能继续。建项的管理名与方案研究编号人工确认合理，但两处确认之间需等待多轮核对。
- **美观性：** 左侧模块导航橙色高亮、步骤标签与白底卡片层级清晰；中央工作区留白较大，重要的研究文档卡片位于下方。灰色等待文案对比度较弱，固定底部操作栏在归属确认处遮挡正文按钮，损害对齐与可点击性；整体配色克制，暂无足够结果视图可评价发现列表的视觉质量。
