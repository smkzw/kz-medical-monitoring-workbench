## 2. 总结论

**FAIL**

**卡点说明**：
数据接入向导第3步在处理研究文档（研究方案与eCRF指南）核对时，触发后端 `study-documents/resolve` 差异仲裁接口。该接口每次耗时约 10~11 秒调用大模型，但在完成仲裁后未成功转移会话状态，导致前端组件重入并无限轮询调用该接口。该无限重入循环不仅使前端处于永久性「系统正在完成最后一次核对」死锁状态（所有输入与确认按钮置灰），而且由于高频密集发起大模型同步计算，彻底耗尽后端并发资源，造成长达数分钟的「整站假死」（导致 `/api/projects` 等全站所有核心 API 发生 15 秒超时 AbortError）。真实用户无法越过此门禁走完全流程。

## 3. 发现清单

### 发现 1：【数据接入向导·第3步】差异仲裁无限死循环与界面永久锁死
- **页面**：医学监查 -> 数据接入向导（Step 3：处理少量疑点 / 研究文档准备情况）
- **问题**：上传研究文件后，系统陷入自动化差异仲裁无限循环，界面永久处于「系统正在完成最后一次核对 无需操作，系统会自行处理两次判断中的差异」，核心操作按钮永久置灰为「正在核对研究文件…」，文件上传输入框亦被置灰，用户被完全剥夺操作权且无法推进流程。
- **严重度**：**Critical**（阻断性缺陷，全链瘫痪）
- **类别**：**product_bug**
- **证据（看到的现象）**：
  1. 页面文本固定显示：`系统正在完成最后一次核对 无需操作，系统会自行处理两次判断中的差异。 系统正在识别并交叉核对…`。
  2. 网络性能跟踪记录到高频交替的接口请求：
     - `POST .../study-documents/resolve` 耗时 9,890ms
     - `POST .../study-documents/resolve` 耗时 68ms
     - `POST .../study-documents/resolve` 耗时 9,792ms
     - `POST .../study-documents/resolve` 耗时 69ms
     （循环往复，持续超过 20 分钟不终止）。
  3. 主按钮 `正在核对研究文件…` 属性 `disabled: true`；文件输入框 `<input multiple accept=".docx,.pdf,.xlsx" disabled type="file">` 亦被禁用；整个向导仅剩「返回上一步」可用。
- **复现步骤**：
  1. 新建项目「MX循R8C-CSU」，进入医学监查模块。
  2. 打开数据接入向导，第1步选择 CSU 合成数据目录或单独选择数据 xlsx 文件并开始导入。
  3. 第2步点击「下一步：让系统核对字段」。
  4. 第3步在「一次选择研究文件」中通过系统文件选择器上传 `MG-K10-CSU-001_临床研究方案_V1.3.docx` 与 `MG-K10-CSU-001_eCRF填写指南_V1.0.docx`（或单独上传方案 docx）。
  5. 观察系统界面与网络请求，等待超过 5 分钟，系统始终停留在此状态。

## 4. 界面评价

### 易用性（Usability）
在向导的前期流程中，系统的引导较为顺畅，步骤定义明确（三步法），且在第1步提供了「选择文件夹」、「选择文件」及「手动填写路径」三种兜底模式，对临床试验复杂的本地数据存放形式具有较好的包容性。然而，易用性在遇到异常或长耗时任务时发生严重断崖：第3步文档核对出现模型仲裁分歧时，系统完全剥夺了用户的自主决策权，既不展示分歧双方的具体内容（例如：启发式判为电子病例报告表 vs 模型判为填写指南），也没有提供人工覆盖（Override）或强制采用按钮，而是强制进入「无需操作，系统会自行处理两次判断中的差异」的黑盒死等状态。用户在等待 10~30 分钟期间无法取消、无法重新选文件（输入框被 disabled），陷入完全无助的状态。

### 逻辑性（Logic & Flow）
系统的业务逻辑闭环和严谨性在设计层面值得肯定，尤其是「数据解析 -> 文档确认 -> 字段核对 -> 方案事实 -> 规则发布 -> 监查运行」的单向防错门禁，充分体现了 GxP 计算机化系统的强校验思维，不存在绕过前置核对的暗门。但其状态机流转逻辑存在致命缺陷：在前端设计了自动 resolve 仲裁机制，却未设计退出条件（Exit Condition）与重试次数上限（Max Retries）；当 resolve 接口返回未解状态时，组件依赖项变更再次触发 resolve 请求，形成了逻辑上的死锁循环（Re-entrant Deadlock）。

### 美观性（Aesthetics & Visual Layout）
整体视觉风格沉稳克制，深蓝色/灰白色调符合严肃医疗软件的规范；字号层级与图标（如步骤状态勾选圈、警告黄色警示条、文件统计面板）具有良好的信息密度。布局对齐方面存在小瑕疵：在 1728px 宽屏下，「开始数据接入」按钮位于极右侧（`left: 1599px`），在部分默认缩放或小视口屏幕下极易被边缘裁切或忽略；此外，数据表结构展开列表中 DM、MH、AE 等卡片的信息排版较为紧凑，在卡片较多时滚动区域未与主视图很好隔离，视觉舒适度仍有提升空间。
