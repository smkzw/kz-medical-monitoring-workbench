## 四、界面评价（一线医学监查专员视角）

### 1. 易用性（Usability）
工作台在主干指引上展现了良好的分步导向思路。「新建项目」弹窗中清晰区分了「项目名称（管理代号）」与「试验药物（药物通用名/代号）」的填写规范，有效避免了临床研究员常犯的混淆错误。数据接入向导明确告知三步流程及支持的文件格式（.csv / .xls / .xlsx / .xlsm），且反复承诺「系统保留项目数据副本，原始文件不会修改」，极大地打消了监查员担心破坏原始锁库 Listing 数据的顾虑。
但易用性的短板集中在**异常状态的反馈与指引**：当通过常规文件选择器上传受阻时，系统机械地抛出「网络连接异常」并诱导反复点击「重试」，没有告知真实的载荷或文件有效性问题，剥夺了用户的自主修正能力；另外，空项目展示「暂停整理」按钮也增加了用户的理解心智负担。

### 2. 逻辑性（Logic）
**状态闭环与严谨的门禁设计（Fail-Closed）是整个系统的突出亮点。**
作为在中心核对过无数受试者原始记录的监查员，我最看重规则与数据的证据链。在数据接入未完成时：
- 医学监查首页醒目提示「字段核对尚未完成，确认完成前不会启动医学监查」；
- 点击「方案事实与规则发布」弹窗，系统直接以红色警告阻断，并完整展开了前置依赖链条（`文件上传与内容核验 → 向导第3步研究文件核对与角色确认 → 监查读取`），明确指出「来源台账的匹配/可使用仅代表文件内容核验通过，监查读取还需研究文件与字段核对」，杜绝了虚假结果外溢；
- 当手动输入不存在路径导入失败时，「来源台账」的事件流水立刻以不可篡改的流水形式记录下 `未通过 · 2026-10-03 16:42:13 · .../RUX · 原因：admission_source_invalid`，满足 GCP 与 21 CFR Part 11 对临床系统审计追踪（Audit Trail）的严格要求。

### 3. 美观性（Aesthetics）
界面整体呈现低饱和度、现代专业的工程工作台质感。背景采用浅灰底（#F6F7F9），正文以深板岩色（#20242A）排版，主行动按钮使用鲜明的康哲品牌橙（#F37021），层级对比分明。
但在**响应式适配与局部样式对齐**上仍需打磨：
- **1280px / 1440px / 1920px 视口实测对比**：在 1440px 与 1920px 下布局舒展无横向滚动，整体对齐良好；但在 1280px 宽度下，顶栏项目元数据区域严重挤压，致使核心的「适应症」文字被截断为省略号；
- **固定像素容器问题**：来源台账的「包含历史版本」开关硬编码了 `width: 85px`，导致文本与图标溢出 72px，破坏了工具栏的整体对齐；
- 另外，底层隐藏的 `<input type="file">` 元素在计算样式中暴露出了不恰当的尺寸，虽未直接破坏主视觉，但表明 CSS 边界细节仍有微调空间。
