## 发现清单

1. 【页面】医学监查→数据接入→字段识别；来源台账。【问题】研究方案在来源台账可读可使用，字段识别却断言“未能从这组文件中读取到可核对的内容”，并保持 0 项，阻断后续全链；错误口径与同项目文件核验状态相矛盾，根因未由 UI 证实。【严重度】critical【类别】product_bug【证据】来源台账该 DOCX 显示“DOCX可读取：2454个证据片段（含2454个段落、17张表）”、角色和研究编号均“匹配”、状态“可使用”；向导在用户确认 eCRF 未提供后显示“研究文件已准备好”，但随即报文件可能扫描版/损坏，字段结果始终 0，监查首页不启动。【复现步骤】在本项目上传指定 XLSX→向导添加指定研究方案→等独立核对→如实标记本次未提供电子病例报告表→保存→查看字段识别；通过 UI 重新加载、刷新并重新进入向导仍可见错误。
2. 【页面】医学监查→数据接入→选择数据；来源台账准入事件流水。【问题】错误类型提示不准确：选了不受支持的 DOCX 作为数据文件后，提交提示“目录不存在或路径不可访问”，没有直接说文件类型不支持。【严重度】medium【类别】product_bug【证据】选择器仍显示“已选择‘所选文件’，共1个文件”；点击“开始导入”显示目录不存在；同项目来源台账记录该 DOCX 准入“未通过”，原因码 `admission_source_invalid`。【复现步骤】在数据文件选择器选择本轮指定研究方案 DOCX→点击“开始导入”→观察错误及准入流水。随后点击“重新开始”，选择指定 XLSX 可成功导入。
3. 【页面】医学监查→数据接入→研究文档核对/字段识别。【问题】异步核对阶段只给“仍在独立核对”“复核最后几个分歧”，字段阶段先长时间显示“正在读取系统识别结果”后固定报完整性失败；没有表级进度、耗时或能解释 0 项与来源台账“可使用”冲突的具体原因，用户无法判断需等待还是更换哪份文件。【严重度】medium【类别】ux_issue【证据】研究文档处理约数分钟内状态从独立核对变化为复核分歧；字段识别在多次间隔数分钟的观察、刷新与重新加载后仍 0 项，唯一操作为“重新加载识别结果”或“返回上一步”。【复现步骤】按上条完成研究文件角色确认→留在字段识别页观察→间隔数分钟刷新并重新打开向导。
4. 【页面】医学监查→数据接入→研究文件角色。【问题】按 UI 说明“保存后重新上传文件并重新核对”寻找补充上传入口时，确认 eCRF 未提供后的页面只呈现字段结果、返回上一步和重新加载；无法在该页补上 eCRF 填写指南，提示的纠正路径不明确。【严重度】medium【类别】ux_issue【证据】文件角色确认前有“一次选择研究文件”的文件选择器，保存后该选择器不再显示；返回上一步只回到 1 文件/10 表/591 行的导入概况。【复现步骤】在角色确认选择“本次未提供电子病例报告表”并保存→字段识别报错→尝试按文案寻找重新上传入口、返回上一步。

## 界面评价

- **易用性：** 数据向导把 10 表结构默认折叠，保留“选择数据→查看导入概况→处理少量疑点”的三段导航，正常 XLSX 的 1/10/591 回执清楚；但上传错误将类型问题写成路径不存在，字段失败又只剩重复加载，用户无法从页面采取有根据的修正动作。
- **逻辑性：** 在 eCRF 角色不确定时要求人确认“未提供”，没有擅自把填写指南认作 eCRF，是审慎的；但来源台账已判研究方案技术可读、角色匹配、可使用，接入向导又说整组文件不可读，这两个项目级判定需要统一解释，不能靠用户猜测。
- **美观性：** 实见页面采用白底卡片、橙色当前步骤和红色错误框；主操作按钮位于卡片右下，层次尚清晰。截图所见上方概览卡占大量空白，导入说明和状态文字灰且小，视线需跨越大段留白才能找到错误与下一步；警告色显著但信息密度偏低。
