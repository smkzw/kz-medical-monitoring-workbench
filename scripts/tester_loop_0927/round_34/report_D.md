## 五、发现质量三分类（深挖样本 7 条：真问题 3 / 误报 2 / 存疑 2）

**真问题（该抓）3条。** 例：**24008 访视失约·W12**——SV!row54 载明 2026-06-20 W12 访视「失约」，系统指出同日存在试验药给药记录，属于必须核查的执行矛盾，Query草稿直接可发；另两条为 22006 左甲状腺素钠（病史确无甲减，提示漏登）、23003 血小板计数降低 3 级 SAE（触发SAE上报核对，分级依据「源记录载明」）。

**误报（冤枉好人）2条。** 例：**24008 阿托伐他汀钙（C014）**——面板自己引用病史「血脂异常（M014，2025-11-08）」，却因规则只拿「高血脂」字面对照而结论「无对应记录」；同模式：孟鲁司特钠片（C034）只对照「哮喘」，无视病史「过敏性鼻炎（M015）」。此类Query发出会在中心浪费时间并损耗系统公信力。

**存疑（说不清）2条。** 例：**22006 头痛**——源记录「3级/肯定有关/SAE否」，系统转述忠实且按源记录定高风险，但「肯定有关」对头痛这类常见AE在源数据层面偏激进，系统只能提示核对、无法判源数据真伪；另一条为 24008 氯雷他定（低风险，医学依据空白，Query为通用模板句，产出价值不明）。

## 六、界面评价

- **易用性**：监查四步向导（方式→范围→关注→确认）一次走通无歧义，每步默认值合理；「发现卡片→旅程→来源证据」每跳都有明确按钮与「返回」路径，不迷路。但结果视图的失败态+「重新读取」是本轮最高频动作（5次），真实用户在第2、3次时会怀疑系统坏了；从旅程回首页丢项目上下文再等重载（F8）同样消磨信任。建议：失败态给出明确原因码与预计恢复时间，长读取加进度/剩余提示。
- **逻辑性**：证据链是本系统最强资产——五条链每一跳内容严格对得上（日期、级别、术语、行号全部一致），Query草稿自动携带规则名+记录区间+核对要点，拿来即用；「分级依据：源记录载明/系统推定」的诚实标注值得肯定。逻辑缺口集中在：旅程头部汇总口径与面板矛盾（F3）、基线/批次机制不可用且无解释（F4）、矛盾类发现只锚定一侧记录（F13）。
- **美观性**：整体专业清爽，品牌一致；概览桑基图（知情同意→筛选→治疗）与旅程八域泳道信息密度高且可读，风险定位右栏结构规整。细节瑕疵：「33 个风险锚\n点」断行别扭、JSON引文未格式化（F11）、1970-01-01 兜底日期（F10）。
