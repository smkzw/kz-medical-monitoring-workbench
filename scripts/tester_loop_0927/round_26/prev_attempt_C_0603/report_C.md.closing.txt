### 2. 核心缺陷摘要（共 6 项发现）

1. **【Critical / product_bug】文件角色裁决控件缺失导致向导死锁**  
   界面警告「研究文件自动核对未完成；可对文件角色作出裁决后重试，或将该文件角色标记为缺失」，但在向导 DOM 中未提供任何单选框、下拉框或标记控件，用户无从自愈。
2. **【Critical / product_bug】轮询 resolve 缺少 batch_id 参数，前端吞错假死**  
   前端向 `/study-documents/resolve` 请求未带 Query 参数 `?batch_id=`，接口持续返回 HTTP 422 `mapping_resolve_batch_id_required`。前端静默捕获该错误并向用户虚假显示「系统正在复核最后几个分歧」，推进按钮置灰，造成死循环。
3. **【High / product_bug】激进指纹去重锁死合规文件重传**  
   用户重新单选合规的方案 DOCX 时，系统直接提示「这组文件与此前上传的内容完全一致，直接复用已有核对结论」，强行绑定历史失败结论。
4. **【Medium / ux_issue】页面刷新导致向导状态丢失**  
   刷新页面后向导自动折叠且退回第 1 步，需要重新填入路径并再次触发恢复。
5. **【Medium / product_bug】初次访问 5178 列表超时报「项目服务暂不可用」**  
   首屏项目列表请求超 20 秒超时，新建项目按钮初次被禁用，重试后恢复。
6. **【Low / ux_issue】方案与 eCRF 缺乏分槽上传引导**  
   单文件选择框混杂多类文档，异常时无法直观定位和单独剔除问题文档。

### 3. 一句话判断
**绝对无法由真实用户独立跑通**：在真实数据与研究文档接入阶段，系统既未提供异常文档的裁决与救济入口，又在底层因接口参数缺失陷入死循环欺骗等待，临床用户在无研发修改代码介入的情况下无法走完全程。
