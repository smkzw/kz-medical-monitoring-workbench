## 三、界面评价（必测项）

**易用性**：三步向导结构与「返回上一步」的进度恢复做得好——刷新、重开向导后 DataListing 数据（59 表/3557 行）与已上传文件都保留，不用重来，这对长任务用户是实打实的减负。但文档核对一旦失败，用户就陷入无效循环：三个出口（重新核对、刷新重开、重新上传）全部回到同一错误，文案只说「请稍后重试」，而「稍后」永远等不来；`Internal Server Error` 这种原始错误字样不应直达终端用户。等待提示（「数分钟到20分钟内推进，超过20分钟会提示停滞」）设计很贴心，可惜停滞提示在本轮实测中从未兑现。

**逻辑性**：发布前置链的说明是本轮最佳文案——「文件上传与内容核验（见『来源台账』）→ 数据接入向导第3步研究文件核对与角色确认 → 字段映射确认」，把我这种新用户下一步该去哪里讲得明明白白；「先完成字段映射确认」的空态卡与「无需按角色分别上传——系统按文件内容自动认领角色」都是清晰的逻辑交代。扣分项：「医学监查首页」按钮与「项目风险概览」标题并存，点击后无任何可见变化，作用不明；「研究文件核对未通过——请按上方原因处理后重试」被渲染在底部按钮排的位置、样式近似按钮，初看会当成可点击按钮去点。

**美观性**：整体干净专业——左侧竖导航图标+文字、当前模块橙色高亮；顶部统计徽章（未读决策/高风险开放/待交接/待审批）图标、文案、数字对齐良好；三步指示条当前步橙色高亮一目了然。不足：第3步的文档角色卡片（研究方案/研究者手册/eCRF）每项独占一行大卡片、右侧大片留白，信息密度偏低；主内容区在大屏下向左偏置（右侧留白明显），重心不均衡。（本项基于页面截图与快照评价。）
