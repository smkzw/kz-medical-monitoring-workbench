### 二、核心发现清单汇总

1. **【F1·Critical】数据接入向导 第3步：研究文件核对失败提示「可对文件角色作出裁决后重试」，但界面完全缺失人工裁决与放行控件（死锁断路）**
   - **类别：** `product_bug`
   - **现象与证据：** 双文件上传后系统核对报错：`研究文件自动核对未完成（诊断：document_authority_candidate_not_promotable）；可对文件角色作出裁决后重试。`，下方主按钮置灰显示 `请先添加所需文件`。检查 DOM 发现 `<section class="monitoring-admission-documents">` 内的列表 `<ul></ul>` 为空，没有任何单选框、下拉框、确认文本框或放行按钮供用户选择角色或确认身份；唯一的次要操作按钮为 `重新核对研究文件`，点击后重试依然直接报错，用户彻底卡死。
   - **根因：** `MedicalMonitoringAdmissionWizard.jsx` 在轮询 `resolveStudyDocuments` 抛出异常时的 catch 块中，硬编码了 `setDocumentState({ phase: "failed", payload: null, ... })`，将 `payload` 清空为 `null`，导致原本在 commit `1007d24` 引入的「身份门人工裁决 / user_choices」全部因 `payload: null` 无法渲染。

2. **【F2·High】数据接入向导 第1步：展开「手动填写数据位置」时操作底栏 `<footer>` 直接遮挡输入框，报 `<footer> intercepts pointer events`**
   - **类别：** `ux_issue` / `product_bug`
   - **现象与证据：** 折叠入口展开后，因父级 `.monitoring-admission-field` 采用固定 CSS Grid（第 5 行轨道锁定为 ~29px），展开的内容溢出 Grid，紧随其后的底栏 `footer.monitoring-admission-actions`（top: 553.86px）直接覆盖在输入框（top: 558.76px）上方，指针事件被拦截，无法直接点击聚焦。

3. **【F3·High】数据接入向导 第3步：单文件上传 scanned PDF 提示「也可勾选跳过本文件」，但界面无任何勾选框或跳过按钮（虚假文案）**
   - **类别：** `product_bug` / `ux_issue`
   - **现象与证据：** 单独上传 `RUX-03-002_eCRF填写指南_V1.0.pdf` 时，系统报 `研究文件未通过完整性核对：未能从这组文件中读取到可核对的内容……若批内有其它可用文件，也可勾选跳过本文件。`，但界面内无任何 checkbox 或跳过操作按钮，提示文案与实际功能脱节。

4. **【F4·High】新建项目表单必填项未预先标记，提交失败后才红字报错；且「项目名称」在顶栏及下拉框中完全丢失**
   - **类别：** `ux_issue`
   - **现象与证据：** 表单无红星 `*` 标识必填；提交时拦截提示补全药物、适应症与分期。且建项后顶部下拉框仅显示试验药物和适应症（如 `磷酸芦可替尼乳膏 · 特应性皮炎 · III期 · MW-III-0F1FB3A3`），填入的管理代号 `MX循R2C-RUX` 彻底沉没。

5. **【F5·Medium】大文件（54表18万行）导入解析与文档分析全程无定量进度反馈（急性子PM体验极差）**
   - **类别：** `ux_issue`
   - **现象与证据：** 导入 18MB、54 张表、180,793 行的真实锁库数据耗时 3 分 10 秒；核对文档耗时 1.5~8 分钟。处理期间按钮仅显示静态 `正在导入…` 或 `正在核对研究文件…`，无进度条、无已解析张数计数（如 `12/54 表`）、无剩余时间提示。

6. **【F6·Medium】页面刷新后瞬态报「功能未配置：当前项目尚未配置该模块的真实来源与执行链路」并偶发向导状态闪烁**
   - **类别：** `product_bug` / `ux_issue`
   - **现象与证据：** 刷新页面重载初期，因异步接口延迟回填，监查主区会瞬态呈现大幅红/灰警示「功能未配置」，来源显示为「未配置当前模块」，误导用户以为项目损坏丢失；向导状态在刷新后先闪回第 1 步，数秒后才跳入第 2 步。

### 三、对「这套系统能否由一名真实用户独立跑通」的一句话判断

> **作为管过多期项目的急性子新员工，独立跑通全链是不可能的任务：系统在 54 表 18 万行大规模数据的底层解析能力上虽然扎实过硬，但前台向导存在致命的“交互死锁”——一旦研究文档核对出现字面不匹配或候选晋升异常，界面虽提示用户进行角色裁决，却因前端状态管理清空了数据载荷而完全不渲染任何裁决和放行控件，用户只能眼睁睁被死锁在向导第 3 步，全链彻底中断。**
