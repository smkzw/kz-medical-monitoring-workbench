### 2.3 阻断确认（修复后可回归验证的接口事实）

> 说明：以下为验证阻断根因所做的应用自身接口调用（与页面同一套前端 API），仅用于定位，不替代页面证据。

- `GET …/data-admissions/latest` → `state: profile_ready`（数据侧就绪）
- `GET …/study-documents` → `ready:false`，4 角色 `missing`（文档核对结果从未落库）
- `POST …/mapping-candidates`：
  - 项目A（20 表混合数据）：**500 `mapping_bridge_failed`**，重试 3 次含 45s 间隔均失败；

- 结论链：文档核对不持久化 → 映射被 422/500 拒绝 → 「先核对字段对应关系」gate 永不解除 → 监查工作区/全量报告/下钻全部不可达。

## 三、问题清单（P0/P1/P2）

### P0（阻断监查主业，必须在 CFDI 前修复）

**P0-1 研究文档上传/核对不持久化，医学监查全流程死锁**
- 复现：医学监查 → 数据接入 → 第三步 → 一次选择研究文件（方案 docx + eCRF 指南 docx/pdf）→ 等待核对终态。任意组合（docx/docx、docx/pdf、单文件/双文件、中文名/ASCII 名）终态均为「研究文件核对未能完成」或永久「补齐少量文件内容」；刷新后文档角色仍全部「尚未添加」。
- 影响：监查模块唯一入口被「先核对字段对应关系」gate 封死，任务要求的 5 项监查工作 0 项可执行。
- 证据：`final_blocker.png`（项目B 终态：方案/eCRF 均「尚未添加」+ gate 文案）；`upload_stuck.png`（「补齐」静止态）。

**P0-2 「还差一项关键信息」确认问题无作答控件（前后端契约缺口）**
- 复现：ASCII 文件名上传后核对推进到 `needs_user_input` 类分支 → 显示「仅需确认：ecrf_guide.docx 中，哪些是当前主文件或必须与主文件一起阅读的补充文件？」→ 页面上唯一可点是「重新选择完整研究文件」，**问题本身没有选项/单选/按钮**。DOM 检查确认问题容器 `<ul>` 为空（前端 `DocumentReadinessPanel` 只渲染 `headline/guidance/roles`，未实现该 phase 的选项交互）。
- 影响：用户被系统提问却被剥夺回答手段，形成第 4 步死锁；且该文案将 eCRF 填写指南误判为「可能与方案竞争主文件地位」的歧义文档，本身是分类器误判（见 P1-4）。

**P0-3 字段映射桥服务端错误（500 mapping_bridge_failed），无自愈**
- 复现：数据接入完成 + 文档就绪前置下调用映射生成（项目A 实测）；重试 3 次（含 45s 间隔）持续 500。前端仅笼统提示「生成字段对应建议时出现问题，本次结果未保存。请重试；如再次失败请联系管理员」，无错误码/请求 ID 展示。
- 影响：即便文档问题修复，映射建议生成仍不可用；CFDI 前无法完成事实物化。

### P1（严重可用性/正确性缺陷）

**P1-1 「选择数据文件夹」语义 = 吸入目录下所有研究的全部数据文件**
- 复现：数据位置填 `/tmp/test_materials`（含 PSO 与另一研究 MG-K10 两份 Data Listing）→ 导入结果 20 表 1051 行，银屑病项目混入荨麻疹研究 10 表。无任何表勾选/排除/告警。
- 影响：单项目监查基线被污染；映射桥 500 的直接嫌疑输入（项目B 纯数据则返回 422 而非 500，印证混合数据触发不同失败路径）。真实 world 中多研究共用目录极常见。
- 期望：导入前列出识别到的文件/研究并允许勾选；或按方案适应症自动过滤并提示排除。

**P1-2 处理中状态依赖「刷新页面」才推进，后台整理进度不可感知**
- 复现：「补齐少量文件内容」「复核最后几个分歧」等阶段文案静止 5–10 分钟（实测 290s/570s 无任何变化），刷新页面后状态立即推进（如出现映射 gate 文案）。
- 影响：用户无从判断是「仍在工作」还是「已挂」；「整理在后台进行时，可以离开页面，稍后再查看」的承诺与实际行为矛盾（离开=卡住）。

**P1-3 核对失败后已选文件全部丢失，必须从零重传**
- 复现：148s 长核对失败后界面回到「研究方案 尚未添加 / eCRF 尚未添加」，重传需重新选择全部文件（原生文件选择器无法批量恢复上次选择）。
- 影响：一次失败循环成本 ≥5 分钟，9 次尝试累计 >60 分钟仍无法成功，用户挫败感极强。

**P1-4 文档角色分类器将 eCRF 填写指南判为「歧义待确认」**
- 复现：上传「CMS-D001-PSO-201_eCRF填写指南_V1.0」类命名清晰的文件，系统提问「哪些是当前主文件…补充文件？」而非直接归入 eCRF 角色。
- 影响：对命名规范的标准研究文档制造无意义的人工确认（且该确认 UI 本身缺失，见 P0-2）。

**P1-5 错误零细节，无法报障**
- 复现：「研究文件核对未能完成，请重新选择完整研究文件；无需逐项确认。」无原因（格式？内容解析？服务超时？）、无错误码、无请求 ID、无「查看详情」。
- 影响：用户、支持、开发三方都无法定位；本测试被迫穷举 9+ 组合。

**P1-6 「重新读取」按钮无效**
- 复现：新项目进入监查工作区即显示橙色警示「当前内容暂不可用／监查范围已更新，请重新确认」→ 点「重新读取」→ 警示不消失（按钮 ref 变化但状态不变），需刷新页面。
- 证据：`upload_stuck.png` 顶部警示块。

### P2（体验/一致性）

1. 全新项目（从未有任何监查范围）即提示「监查范围已更新」——文案与状态不符，误导用户以为漏看了什么。
2. 向导第二步无「返回上一步」：进入表识别结果后无法回到第一步重新选择数据（需收起/展开面板绕行，且绕行后仍停留在第二步）。
3. 底部「请先添加所需文件」置灰按钮常驻所有状态（含「正在核对」处理中态），视觉噪音且语义矛盾（明明正在处理，却说请先添加）。
4. 处理中文文件名（空格+顿号）的 docx 全部失败、改名 ASCII 后才能推进第一关核对——中文临床试验文件命名是行业常态，应原生支持（与 P0-1 叠加，无法完全剥离归因，但 4s 即失败的路径与改名后 148s 的路径差异提示文件名处理存在独立问题）。
5. 数据分析与TFL 模块对已接入数据的项目显示「功能未配置」，模块入口与可用性不一致（空态可以更明确引导）。
6. 「暂停整理」按钮在整个流程任何阶段都可见可点，但从未需要也从未解释暂停后如何恢复。

## 四、「不易用/不易看」专题

### 4.1 上传流程顺畅度：★★☆☆☆
- 三步向导概念（选择数据→看识别结果→核对）清楚，手动填路径回退是亮点。
- 但：文件夹=全量吸入无确认步骤（P1-1）；文档上传无已选文件列表、无上传进度条、无逐文件状态；失败即清空（P1-3）；问答无控件（P0-2）。
- 作为「监查就绪需三类文件齐备」的入口，当前流程在最关键一步反复断链。

### 4.2 进度反馈清晰度：★☆☆☆☆
- 全程用**轮播文案**表达后台阶段：「系统正在独立识别并交叉核对…」→「正在核对研究文档」→「系统仍在独立核对研究文件」→「系统正在完成最后一次核对」→「系统正在复核最后几个分歧」→「系统正在补齐少量文件内容」。问题：
  - 无进度百分比/已处理文件数/预计剩余时间；
  - 文案间会**回跳**（如从「补齐」回到「独立核对」），用户无法建立稳定心智模型；
  - 静止 5–10 分钟无心跳提示，刷新才推进（P1-2）；
  - 失败与卡死的视觉表现完全相同（同一句「正在…」）。
- 「暂停整理」与「可以离开页面」的文案给出的是不可兑现的承诺。

### 4.3 结果可读性：★★★★☆（唯一亮点，但止步于此）
- 表识别卡片信息密度恰当：行数、列数、来源文件、类型、日期范围、缺失计数（`CMENDAT · 缺失 1`）、「受试者标识」角色标注——作为监查员我可以一眼确认接入数据完整性和域齐备性。
- 但一旦进入异常态，可读性骤降：一句话+一个按钮，无证据、无下一步具体指引。
- 顶部风险卡（未读决策/高风险开放/待交接/待审批）在接入未完成时全 0，与页面中央的阻断警示并存，信息层级混乱（`upload_stuck.png`）。

## 五、医学分析质量与反过拟合检查

**结论：无法评价。** 合成数据为本新研究新适应症（银屑病 II 期），系统开发中从未见过——这正是本任务设计反过拟合检验的初衷，但监查分析功能（全量报告、个体/中心下钻、PASI 矩阵、CTCAE 语境、血小板 AE-化验匹配、Query 草稿）全部因 P0 链条不可达。**本报告不做任何臆测性打分。**

为修复后回归验证，附监查员的人工预期要点（依据：页面已展示的表结构与任务背景，非系统输出）：

1. **血小板 AE-化验趋势匹配**：AE 表（38 行，含 AETERM/AESEV/AESER/AEREL/AEOUT）应与 LB_HEM（112 行，LBTEST/LBORRES/LBREF/LBSIGNI）做时间窗对齐，检出「AE 报告血小板降低但化验无对应下降」或反向漏报。合成数据自称含植入线索，此域应为重点。
2. **CM-MH 一致性**：CM（31 行）的用药适应症应与 MH（31 行）病史互证；系统已标出 `CMENDAT 缺失 1`，需进一步判断该例是否ongoing（CMONGO 字段在表内）。
3. **PASI 矩阵**：PASI 宽表（W4/W8/W12/W16）应与 SV 访视窗、EX 暴露日期核对访视窗偏移与缺失模式；银屑病 II 期 W16 后 EOT 逻辑应核对。
4. **ICF-随机时序**：ICF_TRACK（ICFSTATE/ICFVER）与 DM.RANDDT（2026-03-06~04-01）比对知情同意先于随机。
5. **CTCAE 语境**：LB_HEM 的 LBSIGNI 与 AESEV/AESER 交叉，验证 3/4 级化验异常是否触发 SAE 报告。
6. **中心下钻**：SITEID 分布（DM 7 列内）应支持按中心聚合风险。

反过拟合检查同样无法执行；仅能确认**数据接入层**对新研究新表结构（PASI/ICF_TRACK 等银屑病特异域）识别无幻觉、类型/范围标注正确，这是对过拟合的**部分**正面证据（识别层），分析层无证据。

## 六、建议（按优先级）

1. **P0-1/P0-2**：修复文档核对持久化与 needs_user_input 的选项交互（或移除该误判问题，见 P1-4）；这两项不修，产品不可用。
2. **P0-3**：映射桥修复后，将服务端错误码/请求 ID 透传到 UI。
3. **P1-1**：目录导入增加文件/研究勾选确认页；按方案自动过滤跨研究数据。
4. **P1-2**：后台任务增加真实进度（阶段+百分比+心跳时间戳）；状态推进不依赖页面刷新。
5. **P1-3/P1-5**：失败保留已选文件并给出具体原因；提供「重试仅失败文件」。
6. 流程文案统一「处理中/失败/待确认」三态视觉，废除轮播文案。
