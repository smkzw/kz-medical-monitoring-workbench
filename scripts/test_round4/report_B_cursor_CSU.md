## 1. 端到端路径与等待

## 4. 不易用 / 不易看

**上传**  
- Listing：文件夹心智，监察员手里通常是一份 xlsx。手动填目录可用，算过关。  
- 方案/eCRF：一次多选合理。把「eCRF 填写指南」当成「docx 里还有主文件/附件要拆」不合理，也不给勾选。  
- 没有「这就是 eCRF 替代件 / 填写指南」的老实选项。

**进度**  
- Listing：秒级，表卡片密度高，宽屏能看。  
- 文档：3–6 分钟双模型核对，文案在安抚（「无需逐项确认」），按钮在指责（「请先添加」）。视觉上长时间停在同一转圈。  
- 主区「先核对字段对应关系」与向导「还差研究文件」两套话并行，不知道该信哪句。

**结果可读性**  
- 没进入监查结果，无受试者时间轴、无线索列表、无 Query。  
- 能读的只有表识别清单：表名大、来源文件名全，尚可；字段标签错误会误导后续。  
- 顶栏风险数字全 0，热力图明确说「无真实矩阵不展示示例」——这点诚实，好。不要用假热力图。

宽屏：工作台是桌面布局，未测手机。主结果区被空态告警和接入向导上下叠，向导确认区在视口下半，空 `<ul>` 几乎看不见，像「系统还在转」而不是「等你点」。

## 5. 医学分析质量与反过拟合

本研究（抗 IgE、CSU、III 期、UAS、合成 listing）按任务说明对开发是未见过的。闸门前能说的：

**没有明显把旧适应症模板硬套上来**  
- 表名按文件识别出 `UAS`、`LB_HEM`、`ICF_TRACK`，不是银屑病/AD 的 PASI/EASI 壳。  
- 未出现演示用假风险矩阵、假审批项。页上写了「不使用本地示例结果 / 不用固定示例值」。这一点可信。

**过拟合/假设错误出在「研究文件长什么样」**  
- 把单份《eCRF 填写指南》理解成「包内还要拆主文件/补充文件」，选项却渲染不出来。  
- 像是按「完整 eCRF 包 / 多文件卷宗」训练或设计的，遇到指南型 docx 就要求确认，又没有确认控件。  
- 仅方案时核对失败，说明「方案+eCRF」被当成硬门槛，但填写指南又不被承认是 eCRF。监察员按 SOP 带的三类文件，系统不认第三类。

**映射质量（仅识别层）**  
- `SUBJID` → 受试者标识：对。  
- `VISIT` → 访视：对。  
- 日期给出范围、`CMENDAT 缺失 1`：有用。  
- 记录号 `*NUM` 标成受试者标识：错，且像按「含 ID/NUM 就当受试者键」的浅规则，不是看过 CSU eCRF。  
- 大多数医学字段（严重程度、相关性、适应症、检验项）没有中文名。谈不上用了方案词典。

**CTCAE / 安全信号 / Query**  
无输出，不能评价是否会发现「血小板 3 级 AE vs 化验趋势」或「CM 哮喘 vs MH 无哮喘」。  
不能因为系统没跑完就记「未发现=漏检」，只能记 **「功能不可达，线索零验证」**。  
若修复闸门后重测，这两条仍应作为必测植入项。

**定期增量视角**  
没有数据批次、没有「本轮 vs 上轮」、没有连续性面板。当前只像一次不完整的首次接入，不是日常增量监查。

## 7. 建议（按监察员优先级）

1. 修复确认列表渲染：有问句就必须有选项；填写指南应可标成「eCRF 填写指南，作为 eCRF 来源」或「非 eCRF，允许仅方案+listing 继续（并诚实标注 CTCAE 来源不足）」。  
2. 处理中主按钮不要写「请先添加所需文件」；给出文件名 + 已用时间 + 阶段。  
3. 写作版本门禁不得盖住侧栏。  
4. 向导离页后应回到真实后台状态，而不是「尚未添加」。  
5. 接入成功的 listing/方案必须出现在来源台账，页眉要有方案版本和数据批次。  
6. `*NUM` 不得映射为受试者标识。  
7. 闸门修复后必须重跑本试验：CTCAE 版本、血小板 3 级 AE vs LB_HEM、CM 哮喘 vs MH、Query 草稿。
