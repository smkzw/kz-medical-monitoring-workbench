## 2. P0 / P1 / P2 问题清单

### P0

**P0-1 研究方案上传后永久停在「补齐少量文件内容」，监查无法启动**

- **现象：** 选择 2.2 MB 方案 docx 后，文档清单消失，只剩「系统正在补齐少量文件内容 / 暂时无需重新选择全部文件」。无进度、无失败、无超时。主按钮一直是禁用的「请先添加所需文件」。
- **复现：** 新建项目并勾选医学监查 → 数据接入上传 Listing 至第 2 步 → 下一步 → 在「一次选择研究文件」中选方案 docx → 等待。
- **已试恢复（均失败）：** 连续等待 5 / 6 / 10 分钟；离开后再回导致状态回滚；暂停整理后再传；继续整理后再等 2 分钟。
- **影响：** 锁库前监查在真实方案文件上走不通。字段映射、事实物化、全量报告、个例、Query 全部不可达。

**P0-2 已识别的 54 张 Listing 不进入来源台账，项目像「没接过数据」**

- **现象：** 向导已展示 54 表 / 180793 行，来源台账仍是「0 当前登记来源 / 当前筛选条件下没有来源记录」。顶栏「数据批次」一直「未登记批次」，「方案版本」一直「草案」。
- **复现：** 完成 Listing 识别后打开「来源台账」并点刷新。
- **影响：** 医学经理无法从台账确认锁库用的是哪一批、哪一版方案；资料治理与监查工作区脱节。

**P0-3 字段映射被宣布为门禁，但没有可点的核对界面**

- **现象：** 中区文案「先核对字段对应关系，确认完成前不会启动医学监查」，同时「当前项目尚无已选择的监查记录」。可点的只有「开始数据接入」。没有映射表、没有确认按钮、没有「跳过/稍后」。
- **复现：** Listing 识别完成后回到监查首页。
- **影响：** 用户被门禁拦住，又找不到门在哪。

### P1

**P1-1 新建项目对话框把监查当写作附属，且勾选控件错位**

- 对话框标题是「新建医学写作项目 / 新建研究方案项目」，监查只是底部复选框。
- 勾选框落在「研究分期」下方，说明文字漂到对话框右侧，中间大片空白。宽屏下几乎读不成一对。
- 没有研究编号（RUX-03-002）、中心数、数据截止日、锁库目标日。项目被编码成 `MW-III-C1EE01D0`。
- **复现：** 项目总看板 → 新建项目。

**P1-2 空项目用错误态冒充空态**

- 刚创建、尚未选监查记录时，主区是带红边的「当前内容暂不可用 / 监查范围已更新，请重新确认」。
- 真实用户会以为系统坏了，而不是「请先接数据」。
- 离开再回来后，该红条被「先核对字段对应关系」替换，说明空态文案不稳定。

**P1-3 大文件导入几乎没有进度**

- 18 MB / 54 表导入约 99 秒，全程只有按钮「正在导入…」或「正在识别数据结构…」。
- 没有百分比、已处理表、剩余时间、可取消。
- 「暂停整理」在尚未开始整理时就出现，和导入步骤抢语义。

**P1-4 手填数据路径与文件夹选择行为不一致**

- 向导提供「无法选择文件夹时，手动填写数据位置」。
- 填 `/tmp/kz_test_round4/rux_upload`（目录真实存在且含 xlsx）→ 「未找到可导入的数据目录」。
- 同一批文件用系统文件夹选择器可以导入。医学经理在无文件夹选择器的环境会直接失败。

**P1-5 医学写作版本门闸挡住侧栏切换**

- 打开「医学写作」出现「当前版本组合不可进入写作工作区」：前端 `web-6a2584e88ee3cecb`，期望后端 `api-4d7fc34f80c04d19`，当前后端 `api-9c28de2cea445beb`。
- 该告警层拦截指针事件，侧栏「医学监查」点不进去，只能改 URL 逃出。
- 方案本可从写作模块补传，这条路被堵死。

**P1-6 「医学监查首页」实际跳到项目总看板**

- 监查页右上角按钮文案是「医学监查首页」，落地是统一收件箱 / 模块状态矩阵，不是监查工作区。

**P1-7 关键字段角色贴错**

Listing 识别结果（第 2 步，可在页面直接看到）把多种不同字段都标成「受试者标识」：

| 表 | 字段 | 系统角色 | 医学含义 |
|---|---|---|---|
| SUBJ 等 | SUBJID | 受试者标识 | 正确 |
| SUBJ 等 | SUBJSTA | 受试者标识 | 应为受试者状态 |
| SUBJ / IC / DM 等 | PAGELMDT | 受试者标识 | 页修订时间 |
| SUBJ | VISIT | 访视（缺失 241/241） | 受试者页无访视，全缺失仍打访视标签 |
| VSH / VSW / PE / VS | VSREASND / PEREASND 附近 | 受试者标识 | 未做/原因类字段被贴错 |
| DSEOS | DSTERM | 受试者标识 | 研究结束原因 |

若映射带着这些角色进入物化，AE/给药/实验室按受试者聚合会串字段。

**P1-8 方案识别进行中，文档类型清单被拆掉**

- 上传前能看到「研究方案 / IB / eCRF / SAP」四行状态。
- 一开始识别，四行清空，只剩一句「补齐少量文件内容」和空的文件框。用户无法判断方案有没有被收下。

### P2

## 3. 不易用 / 不易看专题

### 上传

- Listing 必须选**文件夹**（`webkitdirectory`），不能直接点一个 xlsx。真实 DM 交付经常是单文件。
- 文件夹选择成功后有绿条「已选择 "_test_rux_upload_round4"，共 1 个文件」，这一段清楚。
- 方案上传控件文案是「一次选择研究文件」，与上面四类文档的对应关系弱：不知道一次选多个会不会自动分类，失败后也不回显类型。
- 手填路径是陷阱：文案鼓励填写，后端找不到目录。

### 进度

- 99 秒导入 + 方案 25 分钟空转，用户能看见的只有一句静态文案。
- 「整理在后台进行时，可以离开页面」与「离开后方案状态回滚」矛盾。
- 「暂停整理」出现在导入/识别阶段，医学经理会以为点了会停掉正在跑的识别；实际暂停后方案照样卡在「补齐」。

### 结果可读性

- 第 2 步把 54 张表的**全部字段**平铺成长页，SUBJ 的 13 列和 PE 的 22 列、LBCHEM 的 34 列同一视觉层级。锁库前需要的是：表是否齐、角色是否对、哪张表缺关键变量。
- 角色用橘色小标签，错贴时非常显眼——这是好事——但没有「可疑角色 / 请确认」汇总，用户要靠扫完全表才发现 SUBJSTA、PAGELMDT 都叫受试者标识。
- 监查主画布长期被一块空白提示占住，真正的向导挤在下面。宽屏上中区空洞、工作区沉底，视线找不到下一步。
- 风险摘要紧急/高/中/低全是「—」，热力图说明「不用示例值」——诚实，但空项目应写成「尚无监查结果」，不要用破折号仪表盘。

## 4. 医学分析质量与反过拟合

### 4.1 能评价的部分：Listing 结构识别（未见过本项目）

本 Listing 是真实脱敏 RUX-03-002 交付，54 张表名/中文标签与 AD III 期局部 JAK 试验一致，不像套用演示库。

页面识别到的表覆盖锁库前我真正会查的域：

| 锁库前关注域 | 系统识别到的表 | 判断 |
|---|---|---|
| 受试者与状态 | SUBJ 241 行 | 有；SUBJSTA 角色错 |
| 知情 / 入排 / 随机 | IC、IE、RAND | 有 |
| 方案偏离 / 访视窗 | SV（2227 行，SVDAT 缺失 168）、UNS、NV、DSEOT/DSEOS | 有访视与结束页；**未见独立 DV/PD 表** |
| AE / MH / CM 一致性 | AE、MH、MHT、CM、PR、AH | 有；AE 含 AESER/AESDTH/AETOXGR 等 |
| 实验室趋势 | LBHEMA 18912、LBCHEM 21957、LBURIN、LBVIROQ、LBHBV、LBHCV、LBTUBE、LBPREG、LBO | 有；血常规/生化行数像长表（一项一行） |
| 给药完整性 | DAA、DAB、ECA（实际用药）、ECB（医嘱用药） | 有 |
| 疗效量表（AD） | IGA、EASI、BSA、SRA/SRB/SRC/SR（SCORAD）、NRS/NRSD、DLQI/CDLQI、QSI/QSD 日记卡 | 有，说明不是套用肿瘤/免疫示范表 |

这支持「结构识别没有明显过拟合到开发用的另一适应症」。表中文名（特应性皮炎诊断、湿疹面积及严重程度指数、Itch NRS、PROMIS 睡眠）也对得上 AD 方案语言。

**缺口是否诚实（仅结构层）：**

- 系统**没有编造**不存在的 PK 浓度表、独立 DV 表或分组揭盲表。
- 它把 Code_List 算进 54 张数据表，这是分类过宽，不是编造临床记录。
- 方案/IB/eCRF/SAP 在卡住之前明确写「尚未添加 / 可稍后添加」，这一段是诚实的。
- 卡住之后清单被清空，用户反而**看不到**「没看到方案」——诚实状态被进度文案盖住。这是呈现问题，不是幻觉临床结论。

**结构层已经露出的医学风险信号（尚未被系统升级成 Finding）：**

- IC：`ICDAT` 缺失 237/241，主知情日期几乎全空，只剩 `ICFDAT`。锁库前必须确认用哪一列做 ICF 日期。
- SUBJ.VISIT 241/241 缺失：受试者页无访视是正常的，系统仍打「访视」标签。
- LBSTRES/LBSTRESU 在血常规、血生化上显示「缺失 = 行数」（标准化结果全空），锁库前实验室趋势只能走原始值 `LBORRES`。
- DSEOS：`DTHDAT` 缺失 192/192，死亡字段空，需与 AE 死亡核对，但系统还没做到这一层。

### 4.2 不能评价的部分（被 P0 挡住）

按任务要求，以下全部**未发生**，不能写成「通过」或「失败于医学逻辑」：

1. 全量风险/AI 线索是否覆盖方案偏离、入排符合性、AE–MH–CM、实验室趋势、给药完整性  
2. 抽查 2–3 例受试者，点开证据链核对系统标注  
3. Query 草稿的医学质量（可执行性、指向字段、是否该发、是否过拟合套话）  
4. 事实物化是否按受试者对齐访视窗、基线、EOT  

**反过拟合总判：** Listing 识别像是按文件内容做的，没有把本试验认成荨麻疹/银屑病演示项目。方案解析和下游监查引擎是否过拟合，**本轮无法检验**——系统没读完方案，也没产出一条 Finding。

## 6. 建议（按锁库前可用性）

1. **先修方案/eCRF 识别闭环：** 有进度、有失败、有超时、有「识别到的文件名 + 类型」。主按钮在文件已选时不要再写「请先添加所需文件」。  
2. **Listing 识别成功即写入来源台账和数据批次**，不要等方案。锁库前可以先看表，再贴方案。  
3. **把「核对字段对应关系」做成真正的一页：** 只列出角色冲突/全缺失/可疑贴标（SUBJSTA、PAGELMDT、VISIT 全空），一键确认后才允许开监查。  
4. **空项目用空态，不用错误态。**  
5. **大文件导入给表级进度。**  
6. 写作模块版本不一致时不要做成全屏指针陷阱。
