## 3. 裁决验收

### 3.1 方案 + 填写指南一起传

选择器显示「2 个文件」，文件名确认是 `MG-K10-CSU-001_protocol.docx` 与填写指南。第一次长等约 8.5 分钟后（以及刷新后第二次 **15s**）稳定文案：

标题仍写「正在核对」。角色区是空 `<ul></ul>`，0 个 radio。页面让人去裁决，控件不存在。主按钮仍是「请先添加所需文件」，尽管已显示「2 个文件」。

### 3.2 逐角色作答（只传填写指南时的单选）

按医学判断：

| 角色 | 应选 | 页面实际能选 | 本次作答 |
| --- | --- | --- | --- |
| 方案 / protocol | 方案 V1.3 docx | 只有填写指南这一份候选 | **标记缺失**（方案文件不在候选里） |
| eCRF | 填写指南 | 填写指南 | **选填写指南** |
| IB | 标记缺失 | 无此角色 | 无法作答 |
| SAP | 标记缺失 | 无此角色 | 无法作答 |

诚实作答后「提交裁决并继续」**仍禁用**。协议角色标缺失不能提交。

把填写指南同时标成 ecrf 和 protocol 后提交钮才启用。这是 UI 逼出来的错误指派，不是监查员判断。

### 3.3 刷新 / 离开再回来

作答（ecrf=填写指南，protocol=缺失）后执行 `reload`：

- 向导收起，只剩「先核对字段对应关系…确认完成前不会启动医学监查」
- 再开向导：第 2 步 10 表还在
- 第 3 步回到四项「尚未添加」、文件「未选择任何文件」、0 个 radio

**未提交的裁决不保留。** 此前未作答就去来源台账，确认界面同样消失。Listing 识别结果保留。

### 3.4 提交后是否推进

- 诚实作答：提交禁用，点了无变化。
- 同一文件双角色（才能点提交）：**4.1s** 后

> 诊断：`document_authority_candidate_role_collision`；可对文件角色作出裁决后重试。

仍停在确认页。监查记录仍是「尚无已选择的监查记录」。字段核对闸门未解除。

死结：缺方案不能提交；补方案走两文件路径没有单选；用同一文件凑齐两个角色会被 collision 打回。

## 8. 反过拟合

对照的是用户给出的 listing 原件和页面原文，不是后台标准答案。

接入层：隔离目录只吃 CSU 一份 xlsx，10 个表名与源工作表一致，英文列名与源表第二行一致，行数加总 573。没有把银屑病 PASI 表编进这个项目。CMENDAT「缺失 1」与源 CM 表唯一空结束日期（22006 / 孟鲁司特）数量相同。系统没有为了「看起来像监查完」去编造血小板故事、哮喘矛盾或 CTCAE 版本。

映射层：`*NUM` 本轮没有再被统一标成「受试者标识」。这是规则收窄，不像针对本试验背题。医学角色（严重程度、相关性、用药目的、检验项）仍然大面积停在「文本/数值」，这是欠拟合，不是把 CSU 答案写进标签。

分析层：没有 Query、没有线索列表、没有「未见异常」。两条预登记线索仍在源文件里。系统既没有命中，也没有写出相反结论。本次不能给医学分析质量打通过，只能给「还没开始分析」打通过。

文件角色层：把填写指南同时标成 ecrf 和 protocol 会触发 `candidate_role_collision`。系统拒绝「一份文件当两个必填角色」，这一点没有过拟合到「填写指南=eCRF」的标准答案；它在候选集合只有一份文件时，把用户逼进这条拒绝。

下面这些话系统没有说，评价时也不算它说过：使用了某一版 CTCAE；UAS7 完整或缺失；方案偏离 / 给药 / 实验室趋势已覆盖；Listing 已作为正式数据批次登记。
